# AutoOps 全新模块化重建计划

执行依据为 [项目入口](../AGENTS.md)、[后端规范](backend-standard.md)、[工程规范](engineering-standard.md)和 [T3 UI 规范](t3-ui-standard.md)。从空业务数据建设，保留当前已确认的公共框架及业务流程，不兼容旧数据和接口；既有验证环境不因重建自动清理或替换。

## 分波交付

| 波次 | 可交付范围 | 退出条件 |
| --- | --- | --- |
| 规范与基础条件 | 精简开发入口、规范索引、工程/后端/UI约束、可执行命令和计划 | 规则无冲突、链接可达、目标与现状可区分，规范提交推送 |
| 第一波：工程基座与权限纵向切片 | 严格 TypeScript、模块边界检查、统一合同/错误、SQLite 升级；本地真实账号与会话、项目/环境/成员及统一授权；独立新产品 API 启动入口 | 空库初始化 → 管理员建立账号 → 内部成员创建项目 → 管理环境/成员 → 按能力访问；跨用户/项目/环境/外部范围、撤权及重启验证通过；有 CI 与可复现命令 |
| 第二波：公共工作台与资料链路 | 接入当前公共壳、新身份与 capabilities；工作区内部版本、外部脱敏/复核、授权浏览、来源和产物合同 | 页面与 API 共用范围；实际文件读写/下载/版本生命周期闭环；工作区 T3 呈现验收通过 |
| 第三波：交付与部署 | 凭证引用、资源连接、服务/部署位置、固定源码包、发布/日志/验证/恢复/历史 | 从内部固定版本到真实目标运行的完整链路及失败恢复通过；发布区按新呈现规范验收 |
| 第四波：问答、技能与客户宿主 | T3 业务身份绑定、模型/强度、技能快照、资料/成果权限、所有者本机执行 | 平台/本机权限分离；原生轮次/队列/重连不被改写；撤权、停用、未知结果及可靠事件验证通过 |
| 第五波：扩展与运营 | 预置 MCP、机柜、授权任务汇总、审计/通知及运维入口 | 同一注册表、合同和授权；只读工具真实只读，启停与历史读取语义完整 |
| 正式启用 | 完整业务回归、备份恢复演练、容量与故障验证、发布及回退操作说明 | 用户确认的功能矩阵全部有证据，新平台独立初始化，无旧兼容回退；按授权切换部署 |

## 第一波边界

先交付可运行且有真实持久化、授权检查的后端切片，不创建十二个空模块，不同时重写全部 UI 或 T3。第一波只开放已实现的动作；未来发布、技能、资料动作可以成为权限设计的测试场景，但不能据此暴露不可用业务入口。

新产品代码有独立组合根和数据目录，旧入口作为参考保留在仓库内；新运行路径不调用旧状态存储或兼容适配器。这是分阶段替换，不是让一个业务操作双写两套系统。上线切换前继续使用既有验证环境，单独记录新切片的使用方法和当前功能范围。

新产品 HTTP 合同以 `/api/v1` 为入口；同一用例可被后续 RPC/MCP 复用。成员归项目模块，授权记录归授权模块，账号/会话归身份模块，审计归审计模块，基础 SQLite 连接/事务不承载业务查询。

第一波必须验证：无默认演示账号；登录身份不能由请求伪造；内部成员创建项目后成为管理员；外部成员不能建项目；普通成员不能管理成员；动作和范围不跨授权拼接；新增环境不自动扩大普通成员授权；停用账号、移除成员/撤权后既有会话立即受限；平台管理员不因全局角色获得私有成果或设备执行权。任务执行前重查、文件下载和 T3 集成在相应波次补实际路径验收，第一波不能宣称已完成。

## 推进与状态

本计划顺序可随明确需求调整，但每波必须完整通过自身退出条件再称为完成。代码入口、实际命令与当前进展只维护在 [开发与验证](../docs/development.md)，不在多份文档重复完成清单。
