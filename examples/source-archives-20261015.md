# 分支发布与中心源码版本档案

发布以中心保存的原始 ZIP、完整 commit 和配置快照为依据。服务器镜像和静态目录是恢复缓存，删除缓存后可由 Agent 1.4.0 从中心档案重新构建。仓库查询、发布选择和历史回退有独立的生命周期。

## 使用方式

1. 添加仓库时填写名称、地址及凭证。中心识别远端默认分支；空仓库、连接失败或无默认分支分别显示状态，不猜测 main/master。
2. 服务配置只关联当前环境仓库。Maven 模块目录填写仓库相对路径，如 `services/api`，不是任意 artifactId；前端目录中必须有 package.json、锁文件和构建脚本。
3. 点击发布，确认目标服务器，搜索选择分支，再选择具体提交。每个部署位置默认使用其运行版本的分支。刷新同一分支保留仍有效的选择，旧提交消失后需要重新选择。
4. 确认框展示分支、提交说明、完整 commit、服务器及配置。源码归档成功后才下发 Agent；配置改变导致确认失效时刷新后重试。
5. 点击服务名称进入详情；在配置页编辑下次发布配置，在发布记录中查看版本、下载源码或回退。历史配置只读，保存配置不会发布。

## 档案和回退

档案位于数据卷的 `deployments/archives/<项目 ID>/<ZIP SHA-256>.zip`。同项目相同 ZIP 共享文件，每个成功版本独立保存来源分支、commit、提交说明、配置和产物记录。不同分支上的相同 commit 不会合并发布来源。

临时文件经 SHA-256、大小校验及同步落盘后原子改名，再登记任务引用。准备阶段重启可从已登记档案继续；未完成文件不能成为可下发版本。中心成功版本全部保留，失败或中断任务独有档案保留 7 天。小时清理只处理失去引用且超过保留期的失败档案。

回退不读取当前仓库开关或服务配置。有效缓存直接恢复，缺失缓存按原 ZIP 和历史配置重建。重建获得新产物 ID，记录恢复来源，不覆盖原版本。切换前保护当前运行版本作为失败恢复基线；基线缺失则先准备基线，无法准备就停止。构建失败不切换，切换后的健康检查失败会恢复操作前版本并分别报告结果。

Agent 保留最近 5 个成功产物及当前版本、基线；中心保留规则不受此数量限制。旧 Agent 不获得重建授权，需升级后使用完整档案恢复能力。

清理操作释放选定版本的档案引用，保留记录与审计。当前运行版本、恢复基线、执行中任务引用不可清理；共享文件直到其他有效引用全部释放后才删除。已清理版本显示“源码已清理”，不能作为中心支持重建的版本。磁盘不足时停止新归档，不删除成功版本腾空间。

## 历史数据迁移

继续使用 SQLite，新增 `deployments.sourceArchives` 元数据。启动时校验旧任务的 source.zip 与已保存摘要，然后导入独立档案并关联版本；重复启动不生成重复档案。原任务和发布快照是来源信息的唯一补齐依据，不使用当前配置填充历史。

缺失的旧 ZIP 标明“中心源码缺失”，损坏档案标明校验异常；不会重新拉取分支最新代码补档。未曾归档但保有可信本机产物的旧记录仍可缓存回退，缓存也不存在时无法恢复。历史任务、仓库与服务 ID、下载密钥、管理员和 Agent 凭据均保留。

迁移统计写入 `deployments.sourceArchiveMigration`，包含 imported、missing、invalid 和执行时间。missing 包括失败任务遗留缺包，不等于成功版本缺失数量；上线报告另外统计成功版本档案状态。

## 升级和恢复步骤

中心仍使用 172.29.254.212，不迁移地址，不操作 Jenkins。本次升级仅替换中心和 Agent 程序，不通过业务任务重建现有业务容器，也不修改静态站点指针或 Nginx。

1. 在隔离 Linux Docker 完成 Java 和前端正常发布、缓存缺失重建、故障恢复、断网和重启验收，再开放升级窗口。
2. 等待中心无 preparing、queued、running 任务。停止接收发布，停止中心后再次检查数据库无未结束任务；若停机窗口出现新任务，启动原中心等待完成后重试，不能带着运行任务升级。
3. 备份完整数据卷，包括 SQLite、master.key、任务源码与日志、档案；保存原中心镜像、Compose、环境文件和代码。备份含秘密，目录权限为 0700，不入 Git。
4. 在备份副本启动新版迁移，不发布端口、不连接 Agent。对比迁移前后管理员、凭证、ID、密钥、当前版本和任务集合；核验档案校验值及缺失记录。验证成功才将新版接入正式数据卷。
5. 检查健康接口、登录、项目数据及已授权历史源码档案，确认固定提交和摘要仍一致。逐台等待 Agent 空闲并备份身份、任务记录、目标版本和静态目录；用原挂载与资源限制更换 Agent，保留旧镜像与停止的旧容器。
6. 确认 Agent 心跳包含 `source-archive-recovery-v1`，核对业务容器 ID、启动时间及静态 current 指针未变化，再开放发布。

中心升级失败时停止新版，保留故障卷用于诊断，用升级前整卷备份和旧镜像成对恢复。Agent 启动失败时停止新容器，恢复同一服务器的原身份和状态，用旧镜像及原挂载启动；不得复制另一台服务器身份。升级窗口内不执行业务发布，因此程序恢复不应改变业务容器或站点版本。
