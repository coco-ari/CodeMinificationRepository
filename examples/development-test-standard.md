# 开发测试阶段的执行与验收

用户于 2026-10-28 确认本规范。适用于当前 AutoOps 开发测试实例，优先于历史记录中的全量数据保留、每次远端 CI、自然七天等待和重复整站验证要求。业务范围、权限及功能正确性不因此改变；正式上线准备与生产环境另启用完整发行和数据保护要求。

本文件维护当前阶段的执行范围；工程方法仍遵循[工程规范](engineering-standard.md)，页面仍遵循[T3 UI 规范](t3-ui-standard.md)，数据边界见[后端规范](backend-standard.md#复用与运行架构)。

## GitHub CI 与本地验证

- 两条 GitHub Actions 工作流仅保留 `workflow_dispatch` 手动入口，取消 `push` 和 `pull_request` 自动触发。当前开发测试的提交、推送及测试发版不等待远端 CI，不为过程记录或文档修改发起完整流水线。
- 本地验证按实际影响选择，不删除原有检查命令、测试或失败恢复覆盖。完整验证命令 `pnpm verify:autoops` 和 `pnpm verify:runtime` 保留，正式上线前对固定候选执行；必要时可在集成批次主动运行，不要求每个小修都运行。
- 纯文档只检查差分、格式、链接与约束一致性；带可执行脚本、工作流或配置的变更需额外检查实际配置和行为。当前两份工作流变更校验 YAML、触发事件及原检查步骤保持即可，不为取消自动 CI 再跑完整业务矩阵。
- 局部代码修改运行相关单测及必要类型、构建检查；公共合同、权限或持久化变更覆盖直接调用方及关键失败恢复。测试发版核对固定提交或产物、实际运行版本、健康及本批真实业务。
- 既有远端分支保护如果要求检查，不能伪造通过或强推绕过；如确实阻塞指定分支合并，说明具体规则并处理该仓库配置，不把未知的远端规则重新加成所有本地开发和测试发版的前置。

## 时间相关验收

- 到期、回收和定时更新可在隔离测试中使用注入时钟或测试专用短周期，运行真实业务代码、存储与清理动作；不更改宿主系统时钟，不只运行替代算法证明成功。
- D6 的生产默认七天及版本链、活动和未知引用保护规则保持。开发验收覆盖未到期不清理、到期且无引用才清理、有引用继续保护，以及清理失败后的重试；采用可重建测试样例。
- 自然七天观察单列为后续长期观察，不作为开发测试主体交付完成的硬等待。受控时间验收与自然观察分别记录，不能将加速测试冒称为已经自然运行七天；D6 的关键功能未通过时仍属未完成。

## 验收辅助工具

- 保留目标实例、操作对象与范围的检查。PID、当前发行路径等动态事实在既定目标内读取并核对，减少手填参数、历史摘要以及复制版本脚本；只有业务确需固定的提交、产物或身份才固定。
- 缺字段或执行上下文问题在实际入口的预检阶段直接报清楚，优先在开始有副作用的操作前发现。必要诊断在断言前保存，保留脱敏后的具体错误和相关差异。
- 产品失败、工具误判和环境不可用分别处理。工具误判先复核已发生的结果，不为取得通过而重复发布或创建业务；对直接阻塞当前工作的工具做最小修改，不扩展新的取证框架、控制卡体系或验收矩阵。

## 界面与集成验证范围

- 局部改动只覆盖受影响入口和相关成功、失败、恢复交互；公共布局或组件再选代表性的浅深主题、桌面、窄屏、长内容和键盘场景，不对每个小修重复穷举整站组合。
- 已有充分证据且代码、依赖和关键条件未受影响时复用结果；更换 Agent、补写文档、恢复测试环境或新建验证脚本本身不构成重跑整套业务的理由。
- 同一固定候选尽量构建一次并复用已验证产物。按可运行批次集成和发布，不把每次局部调整拆成独立整站发行；必要的版本及健康核对保留。

## 记录与小修流程

- 2026-10-29 用户明确要求：小问题修复不进行大量测试。优先复用既有验证，只执行直接相关的定向检查；部署时补必要构建、健康与受影响页面核对，不扩展成整站回归。

- 当前清单每项仅保留代码、自动测试、部署、真实验收状态，以及关键证据入口、阻塞和下一步。每个可交付批次更新一次；历史尝试和长日志留在相应记录，不持续堆入当前状态单元格。
- 有编译诊断、最小失败用例或日志直接证明原因的缺字段、类型、配置等小修，可直接最小修复并复验，不强制凑两个原因。证据不足或跨模块问题才展开多个可验证原因；不能凭猜测修改。
- 普通小修不强制生成三类体验收益、独立长报告或整站操作计数。用户流程改变时，记录受影响核心任务的真实前后步骤、等待及结果；纯文案或样式调整只说明实际差异及相关呈现验证，保留无障碍和错误反馈。
- 规范用于推进交付。只同步直接冲突的现行条款，不重新审查全部历史，也不把整理规范代替原任务；原业务未完成项继续执行。
