# 按服务器配置存储策略

Agent 1.5.0 在「服务器管理 → 存储策略」接收该服务器的版本保留数和平台构建缓存额度。默认分别为 **2 个成功节点、2 GiB**，范围为 2–20 个节点、1–20 GiB。

## 发布链与本机产物

- 每个部署位置单独计算成功链条。发布成功、手动回退成功都新增节点；重启、失败及失败后的自动恢复不新增节点。
- 例如 `A → B → C → 回退 B → 回退 A`，完成最后一步后保留「回退 B」和「回退 A」两个节点引用的产物。它们在中心有独立操作记录和恢复来源。
- 缓存回退的新节点通过 `artifactId` 引用原镜像或静态目录，不重复复制产物。多个保留节点引用同一产物时只占一份空间。
- 缓存缺失时只下载中心保存的原 ZIP，按历史配置重建；不读取当前分支或当前待发布配置来替代历史版本。
- 当前版本在切换前作为恢复基线保留；新版本健康检查及成功结果落盘后才清理旧产物。构建、切换期间会临时存在额外产物。
- 中心成功版本与源码包全部保留，本机清理不修改中心档案。管理员手动清理过的中心档案不保证可重建。

## 下发和执行

`PUT /api/deploy/servers/:id/storage-policy` 接收 `retainedVersions`、`buildCacheGiB`。中心递增策略 `revision`，记入操作记录，通过该服务器的注册或心跳响应下发。Agent 能力为 `storage-policy-v1`。

Agent 将策略保存在自己的身份目录。任务正在执行时等待结束；空闲、策略修改和任务结束后执行维护，并每小时复查。失败一分钟后重试。中心显示待下发、等待任务结束、正在清理、已应用或清理未完成，以及最近执行时间、保留节点数和缓存用量。失联仍保留最后上报结果并标明离线。

Agent 的 `targets/<targetId>/chain.json` 保存成功节点顺序，`releases` 保存保留节点元数据。维护与任务领取串行；非终态任务恢复完成前不运行维护。清理失败不会把已成功的业务发布改成失败，也不会伪报策略达标。

## 平台 Docker 构建缓存

Java 镜像使用每台 Agent 独立的 `cmr-<serverId>` Buildx 构建器，驱动为 `docker-container`。Docker 配置放在 `<agent>/docker-config`，不切换主机默认构建器。BuildKit 容器限制为 512 MiB 内存、768 MiB 内存加交换空间和 1 CPU。

仅对这个构建器执行空闲回收，使用 `--max-used-space`、`--reserved-space 0`。通过构建器内 `buildctl du` 获取精确字节数，回收后再次测量；仍超额就报告未完成。此额度是**空闲清理后的目标**，不是构建过程硬磁盘配额。

额度不包含业务镜像、中心源码包、Maven/npm 依赖缓存、Agent 源码下载缓存和日志。这些空间需分别查看；不会执行 `docker system prune` 或全局 `docker builder prune`。旧默认构建器的共享缓存也不会由新策略自动清除，需确认归属后单独处理。

参考：[Docker 构建缓存清理](https://docs.docker.com/reference/cli/docker/buildx/prune/)、[独立容器构建器](https://docs.docker.com/build/builders/drivers/docker-container/)。

## 升级及恢复

1. 在空闲窗口备份中心 SQLite、密钥和源码档案，确认没有排队或执行中的任务。
2. 更新中心后升级 Agent 为 1.5.0。保留 Agent 身份、任务日志、目标目录、静态目录和 Docker 挂载；升级不重新部署业务容器。
3. 在中心保存策略，等待「已应用」，核对目标节点数量、缓存用量和业务容器状态。
4. 需要回退程序时停止接收新任务，停止新 Agent，恢复备份程序与相应状态，再启动；已经清理的本机产物不能通过恢复旧元数据找回，业务版本恢复应使用中心源码档案。

本次是测试阶段升级，不提供新旧 Agent 混合执行回退任务的兼容逻辑。旧版本记录没有成功链文件时，仅保护当前指针及上一指针；后续成功部署或回退按新链条计算。

## 验证

- 单元及协议回归覆盖 Java/静态站点的连续发布、缓存回退新增节点、旧版本源码重建、重启不入链、失败不入链、中心策略隔离、空闲维护及失败重试。
- 浏览器回归覆盖存储策略保存、输入范围及 390、768、1280、1920 像素宽度。
- `node test/docker-integration.mjs` 使用本地独立 Linux Docker、两个 Agent、Java 演示服务及静态站点，检查镜像和目录确实仅保留最后两个节点的产物；超过五个成功版本后中心原档案仍可恢复。包含真正制造超额缓存并回收到 1 GiB 内的测试，结束时仅移除本次创建的 Builder 和带本次目标标签的镜像。

2026-10-17 本地验收结果：109 项原有及扩展单元/协议测试通过，新增的成功结果写入中断测试单独通过（共 110 项）；更新后的 4 项 HTTP 协议回归再次通过。控制台和公共页面浏览器回归通过。真实 Docker 验收 `32a042cc` 全部通过；独立超额缓存测试从 2,819,839,308 字节清理到 8,192 字节，额度 1,073,741,824 字节。全部使用本地 Docker 隔离资源。
