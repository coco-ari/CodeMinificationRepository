## 产品与访问

内部开发运维团队约 20 人、5 个并发 Agent 任务。按项目组织业务系统，一个项目可含多仓库、服务、任意命名环境。桌面优先且所有操作适配移动端。登录首页为项目列表和全局工具入口；项目概览紧凑呈现环境、服务和近期任务。

采用内部/外部账号分类及角色模板加资源授权：平台管理员、项目管理员、开发成员、发布运维、只读成员和外部协作成员的范围见后端规范。平台管理员管理全部项目，但不能读取他人私有会话、私有成果或控制其本机。内部成员可建项目并成为项目管理员，普通成员不能管理成员或授予权限，外部账号只能加入获授权项目。平台管理员维护账号，项目管理员添加已有账号并分配本项目角色及范围。用户名密码登录、自行改密、管理员重置密码。项目仅必填名称、可选描述、可无环境；不归档，仅删除。运行任务阻止删除；删除平台数据不删除外部服务、数据库或服务器。

## 资料、资源与源码

- 资料有多级目录，创建、上传、改名、移动、删除。仅 Markdown/纯文本在线编辑；图片/PDF/Office 预览或下载。Git 指定路径/目录导入，只读，手动同步。只保留最新内容；仅文件名搜索。
- 资源类型只有 Server/MySQL/Redis。每项目独立凭据；项目公共或属于一个环境。保存立即对未来任务生效，运行任务保留启动快照。测试连接、使用时自动连接、失败重试。预置 MCP；无自定义 MCP 安装、跳板机或 SSH 隧道配置。服务器指标和部署；不提供 SQL/Redis 数据编辑器。
- GitHub/Gitee/自建 Git 公私有仓库；分支、标签或 commit 获取，只读源文件预览。不上传源码 ZIP，第一轮问答 Agent 不改代码或推送。完整项目工作区包含前后端代码、原型、需求和设计等资料，Agent 工作区只分内部原始、外部脱敏两类；以 [工作区与部署包](project-workbench-design.md#工作区与部署包) 为确定的设计基线，当前尚未完整实现。
- 内部原始工作区保留 Git 信息和历史，是唯一原始来源。外部版本从固定内部版本手动单向生成，执行去 Git、脱敏与结果检查，保持相对目录，成功后发布新版本，失败保留上一个可用版本。所有嵌套 `.git` 目录或文件及敏感元数据均纳入处理；正常项目文件按用途保留。代码、文档和原型接受规则检查，无法可靠自动检查的内容先处理或确认再发布；外部报告不暴露敏感明文。处理器可在内部独立复用，去 Git 不再作为第三类工作区入口。
- 前后端源码 ZIP 是部署交付物，直接从内部固定版本按服务构建上下文导出，不从脱敏工作区生成。保留必要构建依赖，记录各仓库完整提交、包 SHA-256、配置引用与任务；对应服务器校验、解压、构建部署并健康检查。页面只保留内部工作区、外部工作区、部署发布三个业务入口。
- 手动删除产物。运行任务和保留的部署版本保护依赖；完成任务/历史会话引用不阻止删除，引用处显示已删除。内部 Agent 经明确授权可使用原始工作区，外部使用固定为已发布脱敏版本；外部版本缺失时要求先生成，不降级读取原始资料。会话固定使用范围和版本，切换内部/外部另开对话，不携带原始会话上下文或跨范围缓存；外部结果不自动反向覆盖内部。私有成果仍需显式保存才进入项目公共资料。

## 服务与发布

Java 源码构建、前端静态构建、已有容器镜像；普通 Linux，单个服务可部署多主机。手工选版本并确认，可多选服务批量上线，各服务独立结果。允许短暂中断。启动/健康检查失败自动恢复上一运行版本，首次发布失败明确报告。可看运行状态、日志、历史版本，手动回退、重启、停止/启动；无卸载操作。任务有进度、取消、快照和失败场景。无 Git 触发、Kubernetes、零停机依赖编排。

## 全局机柜迁移

机柜是跨项目全局池，内部成员可手动使用，外部账号无权访问，不按项目启用。新柜自动注册为未分配。项目每个环境可填鉴权基础地址（HTTP/S，可带端口），自动拼接 `/communication/ybt/api/iot/client/con`；目标名称为项目-环境。支持独立手工完整 URL。自动目标随项目/环境变更；删除后机柜留在池内变为未分配，保留照片。目标可启停，自动名称和地址从项目维护。

列表搜索、状态筛选、分页、选当前页、批量分配、换目标；下一次鉴权生效，不强断已建立 MQTT。显示末次请求、鉴权结果及下发 MQTT 地址，鉴权成功不代表在线。当前分配成功鉴权后方可二维码预览/下载。照片上传替换，删除本地登记需完整 IMEI，重连可重新注册。业务操作仅内部成员可做；全局 MySQL 重置配置和匹配 IP 仅平台管理员可改。

重置/解绑单柜操作：只读预览、完整 IMEI 确认、5 分钟一次性令牌；目标 DNS 匹配配置 IP；状态过期/冲突/缺记录拒绝，支持无需变更和结果待核查，未知结果不自动重试。模拟重置柜与槽位 platform_id 为 2，清空柜代理商/商户/网点/绑定时间；不改路由目标、不改订单/充电宝。全局审计保留操作者/对象/时间/结果。

## Agent 与会话

平台内置 Agent 由管理员管理角色指令、描述与运行配置，仅问答、只读外部查询分析、生成报告文件，不执行部署、数据库修改、机柜迁移或源码处理。自动发现获授权资料，也可显式选择文件/目录/产物；首次消息被持久接受后固定项目、环境、助手及资料版本，环境可为空。

平台内置 Agent 私有或共享到指定项目。私有 Agent 与会话仅本人；共享会话仅对同时具备当前资料与环境访问权的该项目成员开放。变更共享设置同步影响历史会话，必须先明确展示影响并确认。一个会话固定 Agent；换 Agent/环境另开会话。已有历史的 Agent 不将会话跨项目搬迁；要共享到其他项目需新建 Agent，以免带出原项目资料。有使用权的成员可继续/停止共享会话，一个活动轮次。运行中的补充输入支持用户明确选择“引导当前执行”或“排队到下一轮”，取代此前只有排队的约定。运行器不可用时拒绝新提交，不自动切换 Agent。

会话支持澄清、流式回答、工具步骤/参数/结果、引用、停止/继续、队列、浏览器断线/重连与恢复；图片粘贴/上传，MD/文本/PDF/Office 附件。平台输出 Markdown/PDF 和表格 CSV。共享会话文件自动存入项目产物，私有文件仅显式保存才进入项目。

客户本机执行已纳入独立能力范围，按 [客户 Agent 架构](agent-demo-customer-agent-architecture-plan.md) 与后端规范实现。设备属于账号所有者，使用登记目录和本机权限；复用 T3 执行、协议与可靠事件，不能扩大平台只读权限或把客户目录当作中心 cwd。客户首版仅开放已闭环的文本、工具结果、模型/强度与本机技能，附件、共享控制等未闭环能力不因此次重建自动开放。

平台问答、客户本机执行及部署 Agent 各有明确职责与授权范围。下文 2026-10-21 的交互评估保留历史语境，当前复用基线已确定为锁定 T3，不重新开启运行器选型或沿用“仅平台内置”的旧范围限制。

### 会话交互参考与已确认方向（2026-10-21）

Agent 与前端的交互及 UI 统一参考锁定版本 T3 Code，按 [T3 UI 规范](t3-ui-standard.md) 开发；运行中输入保留“引导当前执行或排队到下一轮”语义。原 Multica 与 Solid Glass 方向由本规范替代。当时“第一轮只做平台内置 Agent”的范围限制已被后续客户本机决策替代；以下记录不用于缩减当前已开放能力，实现状态以当前分支及逐项验收记录为准。

已确认的两种操作：

| 操作 | 用户意图 | 行为边界 |
| --- | --- | --- |
| 引导当前执行 | 修正当前问题的方向，例如“先查连接失败原因，报告暂时别生成” | 向当前执行补充要求，在可处理新输入的位置接续；保留已有上下文和已返回内容。不能把“取消当前任务，再执行另一条”冒充引导。 |
| 排队到下一轮 | 追加后续问题，例如“这轮结束后，再整理成检查清单” | 当前轮继续，补充内容明确留在待处理队列，待本轮结束后按顺序执行。 |

两种操作都不隐式切换会话的 Agent、环境或源码版本。如果补充要求需要换环境，沿用新建会话规则并保留待发内容。具体运行器能否接收执行中的文本和附件，在后续技术验证中核对；不能用“已发送”掩盖不支持引导、未送达或已结束的情况。

### 建议的第一轮交互方案（历史提案）

以下为 2026-10-21 的原型提案，保留作业务讨论来源，不是本轮待办；与当前规范冲突时，以锁定 T3 原生流程及后续已确认规则为准。

| 场景 | 建议行为 |
| --- | --- |
| 进入会话 | 点击新建即可进入常驻输入区；Agent、环境和资料范围在输入区附近可见、可调整，首次发送前固定。名称自动生成后可改，不要求先填写完整创建表单。 |
| 运行中输入 | 输入区保持可编辑。发送操作明确显示“加入队列”或“引导本轮”；建议默认排队，可切换引导，停止按钮独立。快捷键行为与可见按钮一致，中文输入法选字不会误发送。 |
| 引导回执 | 区分待送达、执行器已接收、未送达和结果待确认；接收不等于已完成要求。失败保留原消息，允许重试或由用户改为排队。原轮恰好结束时明确提示，不能悄悄重复执行。 |
| 队列 | 紧贴输入区显示待处理消息及附件、发送人；支持编辑、移除、改为引导。尚未处理的队列消息不伪装成已回答的聊天轮次。停止后保留并暂停队列，由用户恢复或清空；共享会话显示操作人，个人草稿不共享。 |
| 草稿和附件 | 每个账号、项目、会话分别保存文字与附件状态。切换会话、刷新和发送失败不丢草稿；上传完成只落回原会话。上传中/失败有明确状态，附件未就绪不允许悄悄漏发；重试和继续保留原轮附件及上下文。 |
| 发送与阅读 | 点击立即显示提交状态，确认接收后清理已发送草稿；失败可编辑重发。流式内容持续更新，代码和表格不反复闪烁；停留底部时跟随，上翻阅读时保持位置，用“查看新回复”返回最新位置。 |
| 工具与澄清 | 默认显示简洁当前动作，展开才看工具参数、结果和完整日志。需要选择时在会话内给选项和自由补充；待澄清问题固定在可见位置，未答复前不让队列越过这一问题继续执行。 |
| 停止、继续和恢复 | 停止保留部分回复、工具过程及产物状态；继续使用此前的上下文，重试失败轮次有独立动作。切页和浏览器断线不等同执行停止；恢复时核对真实执行状态、补齐缺失内容，不能重复消息或重复提交。 |
| 结果与移动端 | 引用文档、源码和报告就地查看，保留返回会话时的阅读位置；支持把明确选中的内容带入追问。手机键盘弹起时输入框和发送/停止仍可见，历史与上下文按需打开。 |

建议以这些真实操作作为下一次原型验收场景：输入半句话后切到另一会话再返回；上传途中切会话；慢网发送失败后重试；连续排队两条再编辑第一条；运行中引导并检查回执；阅读旧消息时持续流式输出；停止半段回答再继续；待澄清时已有队列；断线后恢复缺失片段；手机键盘打开时发送。上述为待评审的验收目标，不是已通过的测试记录。

2026-10-21 优先验证 Agent 交互：当前原型已补充“引导本轮 / 排队”两个操作、队列编辑/移除/转引导、停止保留部分回答并暂停队列、继续/重试使用原附件、个人会话草稿持久化与异步附件归属保护，以及澄清时暂停出队和上翻阅读位置保护。Enter 在运行期间默认排队；当前只演示文本引导，带附件消息需要排队。这些是待用户体验验收的原型行为，不代表真实运行器已接入；模拟引导保留轮次身份与已有输出，并明确显示模拟回执。

本轮不以浏览器内模拟证明真实执行中的送达、断线续传或多人并发正确性。真实运行器连接、待送达/失败回执、服务端事件持久化与权限，以及手机实际键盘弹起后的布局仍需后续验证。先完成这一小模块的交互验收，再安排运行器连接和工作台其他模块开发。

### 实现可行性与复用原则（2026-10-21 初步评估）

用户明确要求先判断实现难度，复杂能力优先安装、复用成熟开源项目。第一轮不以自研 Agent 执行器为目标；需求与原型明确后，再通过实际验证完成技术选型。本节是源码评估，不代表已经部署 Multica 或验证真实模型运行。

| 能力 | 初步判断 | 实现取向 |
| --- | --- | --- |
| 排队到下一轮 | 相对容易；正式实现仍需处理持久化、重复提交、多人操作与停止后的暂停 | 优先复用现成队列机制，补齐本项目会话权限与产品规则 |
| 引导当前执行 | 前端入口简单，执行中的输入接收、准确送达与结束时的竞态依赖运行器 | 复用已支持引导的执行器，不自行重建 Agent 执行循环 |
| 流式回答、停止、继续与恢复 | 成熟项目已有实现，但服务端事件和浏览器状态必须一致 | 复用运行与事件机制，按草稿保留、阅读位置、停止保留及重连去重验收 |
| 直接部署整套 Multica | 有自托管方案；安装服务之后仍需配置运行进程及模型访问 | 作为优先验证候选，不能把安装成功等同于已满足工作台需求 |

已核对 Multica 提交 `47120a4131564175da044d63d897ed9b5d76979a`：

- 聊天队列的 Steer 是优先排队项并取消当前任务，和上述“引导当前执行”不同。
- 真正的执行中补充已具备保存、领取、注入和送达回执，但当前绑定 Issue 任务；接口鉴权、数据库与运行进程均检查 Issue 归属。普通 Chat 不能直接复用这一入口，需补聊天绑定、权限及事件适配。见 [接口检查](https://github.com/multica-ai/multica/blob/47120a4131564175da044d63d897ed9b5d76979a/server/internal/handler/task_supplement.go#L186)、[数据库能力门控](https://github.com/multica-ai/multica/blob/47120a4131564175da044d63d897ed9b5d76979a/server/pkg/db/queries/supplement.sql#L13)及[送达链路](https://github.com/multica-ai/multica/blob/47120a4131564175da044d63d897ed9b5d76979a/server/internal/daemon/task_supplement.go#L128)。
- 其中 Codex 适配器通过已有的 `turn/steer` 协议向指定活动轮次补充文本，说明底层能力可以复用。现成补充接口不支持附件；附件引导不能在原型中宣称已具备。见 [Codex 适配器](https://github.com/multica-ai/multica/blob/47120a4131564175da044d63d897ed9b5d76979a/server/pkg/agent/codex.go#L1953)。

优先比较两条复用路径：部署 Multica 并适配工作台，或接入现有 Agent 运行器并保留本项目界面与业务服务。例如 [Codex 官方平台说明](https://developers.openai.com/blog/codex-as-a-platform)将 app-server 用于产品内的会话、执行和流式事件集成；这是候选能力依据，不代表已确定模型供应商或运行器。

决定路径前需验证四项差异：本项目账号与项目权限如何映射；私有 Chat 如何支持项目共享会话；如何在工具授权层落实只读 MCP 与环境范围；如何分别授权内部原始与外部脱敏工作区，并固定输入版本。第一轮运行进程可集中部署在平台侧，无需引入用户外部主机。此处复用路径的历史评估不覆盖后续已锁定的 T3 交互基准。

复用范围还需遵守当前[许可证](https://github.com/multica-ai/multica/blob/47120a4131564175da044d63d897ed9b5d76979a/LICENSE)：该版本在 Apache 2.0 之外附有条件，单一组织内部使用与向第三方提供服务的条款不同；衍生 UI 要求保留 Multica 标识，纯后端复用也有声明要求。不能按无附加条件的 Apache 2.0 理解或直接复制前端后去除标识。

技术验证至少覆盖：真实运行中补充文本并取得准确回执、连续两条队列按序执行且刷新不丢失、停止保留内容并暂停队列、断线恢复不重复、多成员会话操作权限，以及只读工具边界。送达回执只表示执行器接收，不等于模型已经遵循。验证后选择改动最少且满足需求的路径；不因直接安装的便利而把引导悄悄降级成停止重启。

## 任务与交互规范

任务用于查看一次执行的进度、结果和日志，例如源码获取、脱敏、发布或 Agent 分析；可从模块内查看进度，也可进入统一项目任务页，按类型/状态/发起人筛选，查看启动快照、阶段与日志。

操作记录用于追溯操作者、操作对象、时间和结果，例如谁修改了资源配置、删除了资料或发起了发布。这里的“审计”指这些操作记录，不是新增审批流程。耗时操作可以同时有任务与操作记录；一次普通配置修改通常只需要操作记录。当前入口为“任务与审计”，包含“任务”和“操作审计”两个页签。

站内通知，无外部推送。关键配置、删除和机柜操作保留操作记录，只有管理员清理审计。会话/任务历史手工清理前保留；共享列表与通知不能泄露私有会话。场景覆盖空态、运行、失败、回退、资源或运行器不可用、浏览器断线、未知结果。

使用 T3 原生主题、组件和布局，遵循 [T3 UI 规范](t3-ui-standard.md)；默认简体中文，标题不附装饰副标题。桌面/移动、菜单/弹窗、焦点、减少透明效果和高对比度适配。

## 原型入口与边界

`pnpm dev:prototype`，打开 `http://127.0.0.1:5173/prototype.html`。数据保存在浏览器 `autoops:interactive-prototype:v2`，有重置入口。虚构账号 admin / lin / chen，演示密码均为 `Demo123!`，没有真实凭据。外部连接、Git 获取、构建发布、Agent 输出、机柜业务都是明确标识的模拟；上传编辑、状态流转、权限呈现、下载文件和 ZIP 校验可本地真实交互。该浏览器模拟不构成服务端安全权限边界。普通资料/附件单文件限 2 MiB（浏览器演示存储约束）；机柜照片支持 20 MiB 输入并压缩到最长边 1600。Git 路径和源码使用固定演示文件树，真实任意仓库与运行时将在正式开发接入。旧在线站点尚未更新。
