# 前端工具链与试构建

发布工作台选好分支和具体提交后，可以点击“试构建 · 不发布站点”。试构建允许临时填写项目目录、构建镜像、包管理器准确版本、安装方式、脚本、参数、产物目录和内存限制。这些值只保存到本次任务快照，不写回服务或部署位置。

## 工具链

- 支持 npm、pnpm 和 Yarn Classic 1.22.x。Node 版本由构建镜像决定，与 Agent 自身运行的 Node 无关。
- 预设用于填入常见组合；可以输入经过验证的自定义镜像及 digest。需要 Python、编译器等原生依赖时，应准备独立构建镜像，不在业务宿主机安装工具，也不由平台临时改写源码依赖。
- 默认“锁定安装”：npm 使用 `npm ci`，pnpm 使用 `--frozen-lockfile`，Yarn Classic 使用 `--frozen-lockfile`。对应锁文件必须存在。
- 显式选择“兼容安装”后允许生成或更新工作目录内的锁文件。平台不提交该文件到仓库，后续重建可能解析出不同依赖；需要稳定重建时，应在源码中提交锁文件并改回锁定安装。
- npm 6 使用 `--production=false` 安装构建所需开发依赖，新 npm 使用 `--include=dev`。npm 6 拒绝读取新版锁文件；可以选择匹配的 npm 8。
- “忽略旧项目 peer 冲突”仅对 npm 生效，对应 `--legacy-peer-deps`，不会替换依赖版本或自动修正不兼容的源码。
- 构建参数每行一个。例如 `--mode` 和 `test` 分成两行；实际执行 `npm run build -- --mode test`。

## 试构建与正式发布

试构建与发布共用固定提交、中心源码 ZIP、下载校验、构建容器与产物检查流程。每台服务器仍串行执行任务；构建容器沿用 CPU、内存限制，不挂载 Docker Socket、Agent 身份或线上目录。

试构建检查产物目录包含合法 `index.html`，记录真实 Node/包管理器版本、镜像 digest、文件数量和字节数。成功、失败或中断后清理临时源码、依赖和输出目录。包管理器下载缓存用于后续复用，试构建结果不表示站点 HTTP 或业务接口已验收。

试构建不会读取或切换 `current`，不会准备恢复基线、生成成功发布版本、改变发布链条或触发版本保留规则。执行期间 Agent 重启时报告中断，不重复执行构建。结果在任务记录中显示为“试构建”，正式版本列表不包含它。

验证通过后，按试构建任务快照手动填写正式部署配置，再选择提交发布。平台不会自动把临时参数保存到共享服务配置。

## API 与升级

创建任务使用原项目范围接口 `POST /api/workspaces/:project/tasks`，`action` 为 `build-check`，并提交 `targetId`、`branch`、完整 `revision`、`sourceKey`、`configKey` 和幂等 `requestId`。可选 `buildConfig` 只允许前端构建字段。不能借此更换服务器、源码仓库、健康检查或网络。正式发布拒绝使用 `buildConfig` 临时覆盖。

Agent 1.7.0 上报 `frontend-toolchain-v1`。中心在创建和领取试构建任务时检查能力，防止降级 Agent 执行未知操作。中心不接受试构建任务提交发布版本、恢复基线或切换阶段。

升级前确认没有执行中任务，备份中心数据库和 Agent 身份、任务及版本状态；先更新中心，再更新 Agent。升级只重建平台自身容器，不重建业务容器、不重载 Nginx。失败时恢复上一平台镜像和对应代码，保留原数据与站点目录。
