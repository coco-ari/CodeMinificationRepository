# 控制台体验对比审查（2026-10-16）

本轮以 `a911280` 为基线，审查接入、配置、发布、回退、日志排查及手机布局。基线已经包含服务器直接解绑、统一接入按钮、环境删除、仓库连接状态和逐版本回退等上一轮改动。

仅采纳有明确操作收益且通过交互回归的四项改动。以下是代码和可重复测试的证据，不把工程验证当作用户满意度调查，也不虚构操作耗时提升。

## 参考与取舍

- [Render 手动发布](https://render.com/docs/deploys)：支持选择指定 Commit。项目已经固定提交和配置快照，本轮补上搜索入口，不改发布语义。
- [Render 日志检索](https://render.com/docs/logging)：通过搜索和筛选定位输出。本轮采用不需要学习语法的普通文字搜索，保留原有阶段筛选、实时补读及完整导出。
- [Coolify 配置分组](https://coolify.io/docs/applications/configuration/overview)：按用途组织配置。本轮沿用现有分组，把健康检查的常用字段和高级条件分开，并解释实际执行方式。

不采纳重复的版本比较面板、第二套重新发布按钮、泛化的“智能故障诊断”、自动猜测健康接口或自动复制生产端口。现有版本确认、再次更新和日志入口已经覆盖前两项；后三项没有可靠依据，可能误导操作。保留现有源码下载、参数配置、历史版本和系统管理能力。

## 逐项对比与审查结论

| 改动 | 旧版问题 | 新行为与可核验证据 | 审查 |
| --- | --- | --- | --- |
| 复用同服务已有部署配置 | 新增另一个部署位置只能从默认值开始，要重新找回构建镜像、产物路径、参数和检查条件 | 选择同项目、同服务的已有位置，确认后填入表单；测试取消应用后原输入不变，应用后保存配置与源配置逐项相等（新服务器端口除外），且任务数不增加。静态站点的 pnpm 版本及构建参数也保留 | 通过：减少重复录入及遗漏；不复制环境、服务器身份，不自动发布 |
| 健康检查 | Java 默认同时显示 6 个字段，无法直观看出检查从哪里发起、访问哪个端口 | 默认只显示路径和容器端口，其他 4 项按需展开；动态说明实际 URL、HTTP 状态、响应条件和等待时间。测试 204 / UP / 240 秒 / 7 秒在收起后仍被正确保存和复用 | 通过：首次可见输入从 6 项减到 2 项，保留全部检查能力；说明与 Agent 实现核对 |
| 提交搜索 | 最近 100 条提交只能逐条浏览 | 支持完整 SHA、SHA 前缀、提交说明和作者，忽略大小写；100 条测试记录输入作者或 SHA 后仅剩目标 1 条。无匹配不丢失已选提交，切换分支清空筛选，过滤后的旧提交不会误标“最新提交” | 通过：直接定位已知提交，任务仍携带准确完整 SHA，不自动改变选择 |
| 日志搜索与下载 | 只有阶段筛选和复制全文，查关键字需复制到别处；没有文件导出 | 当前阶段和完整日志都能文字检索，显示匹配行数；测试关键字把 8 行缩至 2 行，清空恢复全文；导出的 Blob 与筛选前全文一致，包含搜索之外的日志。特殊字符按文本处理 | 通过：可在页面内排查，并一键保留完整记录；补读未完成时禁用导出，进行中任务下载截至当时的内容 |

健康检查不是新协议：Java 的 `agent/HealthProbe.java` 访问容器内 `127.0.0.1`；静态站点由 `agent/static-deployment.mjs` 检查站点 HTTP 200、发布标记及可选响应内容。原有超时、失败恢复及构建逻辑不变。

配置复用仅作用于表单中的部署设置，不复制业务配置文件。Profile、运行参数和网络会沿用；确认框和应用后的提示要求检查环境差异。服务器映射端口、静态站点 URL 留空，必须重新填写或主动移除端口映射后才能保存，避免静默复用冲突入口。
