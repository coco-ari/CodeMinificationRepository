## 界面与操作

- 首页只保留“项目”、搜索、新建和项目卡片。去掉项目空间统计、目标数量统计及宣传副标题。
- 项目卡片固定高度；测试、生产及自定义环境在卡片内切换，所有服务放在独立滚动区域。新增服务或任务开始不会撑高卡片。
- 主机资源用三条紧凑进度条表示 CPU、内存和磁盘，明确为整机资源。主机连接与服务运行、健康状态分别显示。没有采集值时显示 `—`。
- 服务行显示仓库、发布分支、当前 commit；完整 SHA 可以点击复制，显示时尾部渐隐。更新按钮直接打开该服务的发布工作台，多服务器部署需要在确认区核对具体服务器。
- 仓库、环境服务、部署目标、发布记录采用紧凑表格；服务详情包含配置、运行状态、版本链和发布日志。配置区可以比较下次发布配置和已部署配置。
- 发布和任务详情使用完整页面。资源配置使用页面编辑器，凭证、一次性密钥及危险操作确认保留 shadcn/ui 对话框。页面切换使用短距离淡入过渡，尊重减少动画设置。
- 延续原有项目和任务地址，增加 `release?target=…`、`configuration?target=…` 地址；可以刷新和直接打开。项目切换关闭旧连接并丢弃迟到响应。

## 真实 Git 版本选择

发布工作台提供两种源码方式：

1. **最新代码**：创建任务后拉取当前环境分支最新提交。
2. **选择 commit**：点击“更新代码”获取当前分支最近 100 条真实提交，选择其中一条后发布。刷新只更新中心缓存，不创建发布任务，也不修改默认 Jenkins 下载分支。

指定 commit 必须来自这个目标当前仓库和分支的提交记录。后端检查完整 SHA、项目归属和源码配置版本；页面打开后源码配置若发生变化，旧选择被拒绝并要求重新选择。不同 commit 的任务不合并；ZIP 与运行配置在各自任务中独立固定。

“已发布版本”用于恢复该目标保留的成功产物和运行配置，包含当前版本、可回退、已清理状态。新版本记录保留仓库和分支快照；较旧记录缺少这些字段时不会猜测其来源。

## 真实流程与旧 Agent 兼容

中心侧记录拉取代码、固定提交、打包 ZIP；Agent 侧记录下载、编译、镜像、更新及检查。每个阶段显示实际记录的耗时，排队时间单独列出。点击阶段可以筛选日志。

安装包升级为 Agent 1.2.0，增加独立镜像阶段和心跳往返耗时。此轮只升级 B 中心，**不自动替换 A 已安装的 Agent**：A 的旧 Agent 继续发布 Java 服务，编译与镜像耗时显示为合并记录，网络延迟显示 `—`。旧任务缺少细分阶段时显示已有的合并阶段，不回填虚构耗时。
