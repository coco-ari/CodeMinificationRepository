## 对比范围

2026-10-16 在原中心 `172.29.254.212` 与测试部署服务器 `129.226.133.152` 验证。服务器为 2 核、约 3.5 GiB 内存；四个 Java 服务继续串行发布。业务代码均固定到 `p-vi-sol` 分支的 `a710bdb3719032716c304df5af4849aecf85c445`，端口继续使用 10110、10111、10112、10115。

旧 Jenkins 脚本的 Maven 容器使用 1.5 核、1024 MiB，而此前 Agent 构建只允许 1 核，三个服务为 768 MiB；Agent 自身还被限制为 0.25 核。同一份 7,815,380 字节的 ZIP 在四个服务间重复下载。此外，中心在配置变更和源码准备阶段提前结束长轮询，Agent 领不到任务后会等待 5 秒再试。

本次没有恢复或运行 Jenkins。以下数据来自本平台在相同提交、同一服务器上的优化前后任务记录，属于单次样本对比。

## 已完成的修改

- 四个 Java 目标的后续构建配置统一为 1.5 核、1024 MiB，保持 Maven 依赖缓存、`clean package` 和模块依赖编译。
- Agent 1.4.2 默认 CPU 上限提高至 0.5 核，内存仍为 256 MiB。
- Java 和前端共用经过校验的完整源码 ZIP 缓存，最近使用的 4 份、合计不超过 128 MiB；测试后实际占用约 7.5 MiB。构建目录仍按任务隔离并清理。
- 缓存按中心、业务项目、仓库、完整提交和 SHA-256 隔离。命中后通过任务 HEAD 接口再次检查授权与中心档案，复制过程中重新计算 SHA-256。缓存损坏则重新下载原包，不能换成最新代码；旧中心不支持 HEAD 时仍使用完整 GET。
- 中心仅在所属节点的任务就绪或结束时唤醒领取请求；Agent 完成任务和补报后立即领取下一项。空闲和失败仍退避，服务器任务仍串行。
- 日志单独显示下载或缓存复用、解压与权限准备耗时，保留完整健康检查、资源归属检查、版本归档和失败恢复。
