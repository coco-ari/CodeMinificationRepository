# 第一版验收矩阵

记录日期：2026-10-14。验收范围为中心、Agent、独立 Java 演示环境，以及远程中心升级后的只读并行观察。现有四个 Java 服务继续由 Jenkins 管理，本轮未触发业务重新发布或接管。

## 证据分类

- **逻辑/模拟**：真实文件、SQLite 和业务代码，但 Docker 由测试实现替代，不能证明镜像、文件权限或实际容器恢复正确。
- **真实 HTTP**：真实中心接口、Agent 客户端、鉴权和持久数据；协议测试中的 Docker 仍为模拟实现。
- **浏览器**：本地用真实管理页面与中心接口、模拟 Agent 状态验证交互；远程只读浏览器验证使用真实 Agent 采集数据。两类结果分别记录，不能代替容器故障恢复验收。
- **真实 Docker**：Linux Docker 引擎、两个 Agent、Maven 编译和 Java 演示容器；所有资源采用独立测试标识。

测试名称存在仅说明有覆盖代码。真实 Docker 结果应同时核对命令退出码、报告中的 `passed`、各场景记录及日志；失败时也会写报告，部分成功任务不能证明整轮通过。

## 本轮审查修正

- 未知内存、磁盘值曾被页面换算成 `0.0 GB`：已增加空值判断；最小真实浏览器验证未知显示为 `— / —`，实际零值仍显示 `0.0 GB`。
- 发布详情曾遗漏 `result.error`、回退错误和清理错误：已显示原始原因，最小真实浏览器验证 HTML 内容按文本转义。
- Agent 升级保留身份后，中心原先不更新心跳版本：已增加版本更新与兼容旧客户端的回归用例。
- HTTP 协议测试原先未关闭旧 Agent 就重建实例，Windows 无锁分支掩盖 Linux 冲突：已显式释放旧实例锁，并在清理阶段关闭所有 Runner。
- 未确认日志原先一次性加载成数组：已改为异步迭代逐条补报，构建输出落盘时暂停读取，避免无限堆积待写日志。
- 固定源码原先使用全局归档锁，影响不同项目并行：已按项目分锁，新增不同项目并发及不阻塞另一项目 Jenkins 同步的用例。
- 离线事件补报原先按接收时间记录阶段，造成耗时失真：已保留 Agent 事件时间，并增加两条时间戳补报回归用例。
