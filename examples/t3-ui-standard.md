# T3 UI 统一规范与开发提示词

本规范用于 AutoOps 后续所有页面、交互原型和新增功能。自本次切换起，T3 Code 是唯一 UI 与 Agent 交互主参考，替代早期 Solid Glass 材质与强制 Radix 的要求。业务需求仍由项目需求文档决定；不能因为上游是编程工具，就给用户增加无关的仓库、终端或模型配置步骤。

## 固定参考与实现边界

- 源码基线：[T3 Code](https://github.com/pingdotgg/t3code/tree/fe27e8e3dc12dcbb108e9a28fd9b8cb65f34ae92)，v0.1.1，提交 `fe27e8e3dc12dcbb108e9a28fd9b8cb65f34ae92`。以本仓库 `vendor/t3code/.autoops-source/manifest.json` 和文件清单核对来源，不能静默改用最新版。
- 前端采用 T3 的 React、TypeScript、Tailwind CSS 4、TanStack Router 和 React Compiler。组件以 `vendor/t3code/apps/web/src/components/ui/` 为准，shadcn 配置为 `base-mira`、Zinc、Lucide；原生交互底层为 Base UI。组件注册源不等于另一个设计系统。
- 复用优先顺序：已有 T3 模块 → T3 组件组合/变体 → 按同一模式补充缺失业务组件。新增按钮、菜单、选择器、对话框、提示等不得在业务页另造一套。
- 当前迁入版本仍有为旧要求制作的 Radix 兼容层，接口与外观沿用 T3。这不等于已恢复全部原生 Base UI。后续替换必须逐组件验证焦点、键盘、浮层和触屏，不能为追求依赖名称一致而覆盖已验证的业务适配。
- AutoOps 登录、身份、项目/环境、共享权限、资料、报告与执行工具保留在适配边界。UI 重构不修改协议枚举、鉴权、数据归属、模型配置和存量对话。
- 当前 Demo 的开放范围以 [精简版能力边界](agent-demo-lite-profile.md) 为准：对已开放模块复用完整原生流程，并不要求把 T3 所有功能都展示出来。收起的模块保留源码与历史读取能力，后续统一通过产品能力配置恢复，禁止零散加回入口。

## 视觉与布局

风格是克制、紧凑、内容优先的桌面工作工具。沿用 T3 导航层次、主内容列、贴边工具栏、菜单位置和信息密度。不要增加大面积营销渐变、厚重玻璃卡片、巨型圆角、每行阴影或重复状态徽标。

| 项目     | 统一做法                                                                                                                                                                                 |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 颜色     | 使用 `background`、`foreground`、`muted`、`border`、`accent`、`primary`、语义状态等现有主题 token，不在业务页硬编码另一套色板。默认 T3 Code 浅色，保留用户已选主题、深色和跟随系统设置。 |
| 主题来源 | `apps/web/src/index.css`、`themePalette.ts` 与 `packages/shared/src/themePalettes.ts`。不再导入旧 Solid Glass 全局覆盖；T3 自带的 `surface-glass` 仍按原组件使用。                       |
| 字体     | 使用 `--font-sans`、`--font-mono` 和外观设置中的字号变量，中文使用系统字体回退。代码保留等宽字体，不全局覆盖用户字体设置。                                                               |
| 几何     | 优先用原组件变量；基线 `--control-radius: .5rem`、顶部 `52px`、对话正文最大宽 `46rem`、详情栏 `17.5rem`。这些是复用原布局的参考，不是给所有业务容器强加固定宽高。                        |
| 间距     | 沿用现有 Tailwind 间距与 `--workspace-gutter`，桌面与窄屏按原断点处理；不通过大量空白营造层次。                                                                                          |
| 控件     | 选择组件已有 `variant`、`size`、`density`。外观由组件拥有，调用处只布置布局；通用新外观先成为共享变体。                                                                                  |
| 面板     | 设置用原设置行/分组，清单用连续列表或表格，详情按需展开；不把每个字段包装成独立卡片。                                                                                                    |
| 文案层级 | 一层标题与操作区；辅助信息使用弱化文字，真实业务状态单独表达。保留表单帮助与错误，不增加泛化副标题。                                                                                     |
| 动效     | 保留 T3 动作时机与短过渡，默认跟随系统的减少动态效果设置。外观中的“界面动效”可选择跟随系统、开启或关闭；显式开启时可独立于系统设置。CSS 与 JavaScript 使用同一有效偏好，后台与不可见动画仍暂停。 |

## Agent 问答流程

优先复用 `ChatView`、`components/chat/`、原输入编辑器、虚拟时间线、Markdown、命令与投影，不再实现平行的聊天状态机。

1. 输入、附件、资料上下文、斜杠命令与快捷键使用原输入区结构；支持中文输入法，组合输入期间不能误发送。发送后清空、失败恢复、草稿与暂存按原流程处理。
2. 执行中沿用“引导当前执行”和“排队到下一轮”的原操作语义与能力判断；停止、队列编辑、取消、暂存和恢复保持各自状态。没有后端能力时显示真实限制。
3. 等待、运行、工具调用、提问、授权、完成、失败和中断由真实事件驱动。只展示模型实际返回且允许公开的推理摘要；不伪造思考过程，不把工具结果改成虚假的推理。
4. 工具活动沿用原聚合、折叠、详情与结果展示规则，资料读取走同一工具项；不另加重复进度卡、重复完成提示或内部实现说明。
5. 流式正文沿用原增量渲染、Markdown 和代码高亮。历史沿用分页、虚拟化与懒加载；不为中文化或视觉效果增加全量重绘。
6. 在底部时自动跟随，向上阅读时保持位置；新内容提示与回到底部使用原控件。展开工具、加载旧记录、切换对话与重连都要保住阅读位置。
7. 已开放的复制、重试等动作沿用原位置、显隐和确认时机。精简版不开放新计划、分支与历史回退，旧记录仍可阅读；恢复这些能力时必须同步原生权限、菜单、快捷键与设置。
8. 刷新与断线恢复使用原游标、事件去重和持久状态。不得显示假成功、自动重复执行或丢弃排队和草稿。

## 中文界面规范

默认语言为 `zh-CN`。翻译源代码中的展示文案与动态模板，包含设置、导航、菜单、Tooltip、占位符、ARIA、通知、确认、错误和空态；日期与数字使用中文地区格式。不要通过 DOM 文本替换、MutationObserver、CSS 伪元素或覆盖用户数据实现翻译。

| 原词                                  | 界面统一用词                            |
| ------------------------------------- | --------------------------------------- |
| Thread / Conversation                 | 对话                                    |
| Turn                                  | 轮次                                    |
| Project / Environment                 | 项目 / 环境                             |
| Agent                                 | 智能体（品牌或产品名称中的 Agent 保留） |
| Queue / Queued                        | 队列 / 已排队                           |
| Steer                                 | 引导当前执行                            |
| Stash                                 | 暂存                                    |
| Plan / Implement plan                 | 计划 / 执行计划                         |
| Fork / Branch thread                  | 创建分支对话                            |
| Archive / Unarchive                   | 归档 / 取消归档                         |
| Tool / Tool result                    | 工具 / 工具结果                         |
| Reasoning                             | 思考过程（仅真实可公开内容）            |
| Settings / Appearance / General       | 设置 / 外观 / 常规                      |
| Pending / Running / Failed / Canceled | 等待中 / 执行中 / 失败 / 已取消         |

保留 T3 Code、AutoOps、Codex、Grok 等品牌与模型名，API、URL、JSON 等技术标识，快捷键、命令、协议值、存储键、文件名、路径、代码、许可证法律原文以及用户/模型原文。主题和字体的注册名称不改 ID；可在展示层补中文名称。

## 验收要求

按改动范围检查真实页面：设置入口与搜索、导航、输入、菜单、弹窗、焦点恢复、键盘和中文输入。覆盖浅/深色、系统主题、390px 窄屏、常规桌面、长中文及减少动态效果。对话变动另查运行中输入、队列/停止、向上阅读、回到底部、刷新与重连；不得用截图代替时序验收。

执行相关类型检查、构建及必要的定向测试，保留第三方许可。记录已测和未测的边界；不能因代码迁入就声称全部上游能力均已验证。UI 静态资源发布优先避免重启活动执行进程，不触碰用户历史数据。

## 可直接复用的开发提示词

```text
你正在开发 AutoOps 聚合工作台。先阅读 AGENTS.md 与 examples/t3-ui-standard.md。

所有 UI 以仓库内锁定的 T3 Code v0.1.1 为唯一基准。先找到对应上游组件、布局与状态流程，说明复用点，再实施需求。使用 T3 的主题 token、字体、间距、原组件与变体；新控件沿用原生 Base UI 组合，不扩展旧 Radix 兼容层，不混入 Solid Glass 或其他项目的设计系统。

保持 T3 的内容优先、紧凑导航、轻边框、克制层次与响应式布局。标题只保留标题和操作区，不加装饰副标题。控件外观在共享组件中维护，业务页面只组合与布局，不手写替代控件或硬编码另一套配色、圆角和阴影。

Agent 输入、引导/排队、停止、草稿、工具活动、提问、流式时间线、自动滚动、历史与恢复必须复用 T3 完整流程。展示真实事件与允许公开的内容，不伪造思考、进度或完成，不重复展示工具流程，不为翻译重写状态机。

界面默认简体中文，包括菜单、提示、ARIA、错误和空态，术语与日期遵循规范。保留品牌、模型、代码、协议值、路径、用户与模型原文。直接翻译展示层，不修改业务数据，不做 DOM 事后替换。

AutoOps 的身份、权限、项目/环境、资料和报告接在适配边界。没有上游对应功能时，先按现有 T3 组件模式设计最小业务组合，说明适配原因；不发明第二套交互系统。

当前 Demo 采用 examples/agent-demo-lite-profile.md 的精简能力配置。复用完整流程只针对已开放能力；不重新展示已关闭的计划、分支、回退或开发功能。保留可用的 T3 外观设置与历史内容，关闭能力须同时覆盖界面和后端。

完成后运行与改动相关的类型检查、构建和页面验证，检查浅深色、窄屏、键盘与焦点；涉及对话时验证流式、滚动和运行中操作。报告实际改动、复用来源、验证结果与未覆盖项。未经明确需求，不改变模型配置、权限、协议和存量数据。

工作区与对话整合时，复用 `ComposerSurface.ContextStrip`、`ComposerControl`、原生菜单及标签压缩逻辑，范围选择放在输入框下方。目录和预览复用 `FileBrowserPanel`、`FilePreviewPanel`、`AttachmentFilePreview`、右侧面板与窄屏侧栏，只适配授权数据源。显示项目相对路径，引用保持固定版本的完整身份；不另写递归树或源码预览器。管理页与对话页共用这套文件交互。

T3 主聊天组件依赖 React Compiler 缓存。不要在渲染或 JSX 属性中读取 `ref.current`，发送状态使用原生 `isSendBusy`；事件与 effect 内的 ref 判重保留。相关改动须通过 `test/t3-chatview-compiler.test.mjs`，仅类型检查通过不足以证明页面能运行。相邻报告与文件组件切换版本时使用不同前缀的 key，避免旧区域残留。
```
