# T3 UI 统一规范与开发提示词

本规范用于 AutoOps 后续所有页面、交互原型和新增功能。自本次切换起，T3 Code 是唯一 UI 与 Agent 交互主参考，替代早期 Solid Glass 材质与强制 Radix 的要求。业务需求仍由项目需求文档决定；不能因为上游是编程工具，就给用户增加无关的仓库、终端或模型配置步骤。

## 固定参考与实现边界

- 源码基线：[T3 Code](https://github.com/pingdotgg/t3code/tree/fe27e8e3dc12dcbb108e9a28fd9b8cb65f34ae92)，v0.1.1，提交 `fe27e8e3dc12dcbb108e9a28fd9b8cb65f34ae92`。以本仓库 `vendor/t3code/.autoops-source/manifest.json` 和文件清单核对来源，不能静默改用最新版。
- 前端采用 T3 的 React、TypeScript、Tailwind CSS 4、TanStack Router 和 React Compiler。组件以 `vendor/t3code/apps/web/src/components/ui/` 为准，shadcn 配置为 `base-mira`、Zinc、Lucide；原生交互底层为 Base UI。组件注册源不等于另一个设计系统。
- 复用优先顺序：已有 T3 模块 → T3 组件组合/变体 → 按同一模式补充缺失业务组件。新增按钮、菜单、选择器、对话框、提示等不得在业务页另造一套。
- 技能管理的信息结构和分配操作按用户确认的 Skills Manager `MySkills`／`SyncDots` 流程适配：技能卡片直接切换助手，在同一技能上管理项目。视觉及基础交互组件仍采用 T3；不照搬 Skills Manager 的桌面材质、preset 或安装路径设置。
- 当前迁入版本仍有为旧要求制作的 Radix 兼容层，接口与外观沿用 T3。这不等于已恢复全部原生 Base UI。后续替换必须逐组件验证焦点、键盘、浮层和触屏，不能为追求依赖名称一致而覆盖已验证的业务适配。
- AutoOps 登录、身份、项目/环境、共享权限、资料、报告与执行工具保留在适配边界。UI 重构不修改协议枚举、鉴权、数据归属、模型配置和存量对话。
- 当前 Demo 的开放范围以 [精简版能力边界](agent-demo-lite-profile.md) 为准：对已开放模块复用完整原生流程，并不要求把 T3 所有功能都展示出来。收起的模块保留源码与历史读取能力，后续统一通过产品能力配置恢复，禁止零散加回入口。

## 视觉与布局

风格是克制、紧凑、内容优先的桌面工作工具。沿用 T3 页面骨架、主内容列、贴边工具栏、菜单模式和信息密度；全局项目与模块入口按下文的 AutoOps 顶部导航组合实现。不要增加大面积营销渐变、厚重玻璃卡片、巨型圆角、每行阴影或重复状态徽标。

| 项目     | 统一做法                                                                                                                                                                                 |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 颜色     | 使用 `background`、`foreground`、`muted`、`border`、`accent`、`primary`、语义状态等现有主题 token，不在业务页硬编码另一套色板。默认 T3 Code 浅色，保留用户已选主题、深色和跟随系统设置。 |
| 主题来源 | `apps/web/src/index.css`、`themePalette.ts` 与 `packages/shared/src/themePalettes.ts`。不再导入旧 Solid Glass 全局覆盖；T3 自带的 `surface-glass` 仍按原组件使用。                       |
| 字体     | 使用 `--font-sans`、`--font-mono` 和外观设置中的字号变量，中文使用系统字体回退。代码保留等宽字体，不全局覆盖用户字体设置。                                                               |
| 几何     | 优先用原组件变量；基线 `--control-radius: .5rem`、顶部 `52px`、对话正文最大宽 `46rem`、详情栏 `17.5rem`。这些是复用原布局的参考，不是给所有业务容器强加固定宽高。                        |
| 间距     | 沿用现有 Tailwind 间距与 `--workspace-gutter`，桌面与窄屏按原断点处理；不通过大量空白营造层次。                                                                                          |
| 控件     | 选择组件已有 `variant`、`size`、`density`。外观由组件拥有，调用处只布置布局；通用新外观先成为共享变体。                                                                                  |
| 面板     | 设置用原设置行/分组，清单用连续列表或表格，详情按需展开；不把每个字段包装成独立卡片。                                                                                                    |
| 文案层级 | 一层标题与操作区；辅助信息使用弱化文字，真实业务状态单独表达。保留表单帮助与错误，不增加泛化副标题。                                                                                     |
| 动效     | 保留 T3 动作时机与短过渡，默认跟随系统的减少动态效果设置。外观中的“界面动效”可选择跟随系统、开启或关闭；显式开启时可独立于系统设置。CSS 与 JavaScript 使用同一有效偏好，后台与不可见动画仍暂停。 |

精简版对话侧栏复用 T3 原生 `slim` 单行变体，桌面沿用紧凑行高，触屏保留至少 44px 的点击高度。项目名称由全宽顶部项目选择器统一展示，会话行保留原项目图标与详情提示，不再另加全局范围标题或项目选择。运行、等待回复、失败、未读及置顶等真实状态必须保留；草稿、搜索、菜单、焦点和拖拽继续使用原组件流程。搜索命中的真实内容摘要按需保留，不为统一行高丢失检索证据，也不通过缩小全局字号提高密度。长标题和草稿必须在侧栏视窗内真实省略，不能撑宽滚动内容或裁掉右侧状态和操作。更多操作在悬停、键盘聚焦与触屏下可达；菜单应沿用当前浮层的焦点边界，关闭后恢复入口焦点。

紧凑行的状态与操作沿用 T3 尾部区域复用方式，不把透明的更多或删除按钮再作为独立列挤占标题。桌面悬停与键盘聚焦切换同一尾槽中的展示，标题宽度保持稳定；触屏保留同时可见的状态与操作，并让实际触区留在尾槽及侧栏视窗内。可交互的提醒状态不得因切换操作而留下不可见的焦点目标。未发送草稿的标记与删除入口遵循同一规则，继续使用原有操作组件和处理流程。

## 整页统一与工作区页面

开始实现前，先确定最相近的 T3 完整模块及其布局、操作入口与状态流程。风格统一包含页面骨架、分栏、工具栏、密度、状态反馈、滚动、响应式和键盘焦点；只使用相同按钮与主题不能视为完整适配。没有直接对应的业务页面时，组合原生模块，并明确业务差异，不另套通用后台模板。

项目与模块导航统一放在全宽 `52px` 顶部栏，不占用左侧内容列。项目下拉只列授权项目；桌面“问答、工作区、部署发布”三个常用模块使用 T3 原生 `ToggleGroup`，更多功能使用可搜索 `Combobox`；窄屏将模块入口合并为“切换模块”。常用按钮、更多功能和窄屏菜单来自同一授权功能注册表，当前列出已闭环的问答、工作区、部署发布、技能库及常规、外观、归档，部署入口继续限制为获授权的内部项目管理者。未来 MCP、插件完成权限、数据和操作闭环后通过同一注册表加入，当前不展示未实现的占位入口。

各模块使用独立路由，内容填满顶部栏下的剩余高度，不把部署页嵌入工作区分类，也不重复增加页面内项目选择。左侧仅承载当前模块自己的会话、文件或服务列表：问答保留原生紧凑会话列表，工作区与部署页不保留空的全局侧栏，也不常驻会话列表。复用 `WorkspacePageHeader`、项目 `Combobox`、原生 `ToggleGroup` 及满高内容面板组合；这是 AutoOps 业务导航适配，不声称上游已有相同顶部模块或部署页面。

工作区管理采用文件工作区布局，主要内容使用剩余高度。区域与版本选择、常用操作位于贴边工具栏，窄屏将次要动作收入原生菜单。内部与外部区域共用文件目录和预览；部署页独立提供服务发布、源码包及所选清单预览，包始终从内部固定版本生成。版本标识、哈希与来源等元数据按需查看，导入、脱敏、人工复核和任务详情通过原生弹窗操作。不得把管理页做成纵向表单集合，再嵌入带卡片边框和固定高度的文件浏览器。

项目为全局浏览上下文，环境与版本仍按各业务选择；已开始的对话和发布任务保持原绑定。切项目/区域只导航，不能取消执行、携带旧项目输入到新草稿或更换待确认发布的包。按用户与项目恢复草稿、查看版本、目录与文件、部署目标和任务；原生对话深链以实际归属为准，页面深链校验项目和版本权限。无效项目显示不可用，不回退到其它项目执行操作。设置页同样显示顶部项目选择；设置内切项目留在当前设置页，返回时在当前项目下恢复原业务区域，部署权限不足时返回工作区，不向旧会话路径拼接新项目。刷新、前进后退与跨区域来源跳转必须保持相同身份。

| 场景 | 必须复用的模块或模式 | AutoOps 适配边界 |
| --- | --- | --- |
| 全局项目与模块导航 | `WorkspacePageHeader`、项目 `Combobox`、原生 `ToggleGroup`、可搜索 `Combobox` | 全宽 `52px` 顶栏；同一授权功能注册表；窄屏合并模块入口 |
| 页面与工具栏 | `WorkspacePageHeader`、`SidebarInset`、`files/fileSurfaceChrome` | 项目、内部/外部固定版本、真实发布状态 |
| 目录与内容 | `FileBrowserPanel`、`AttachmentFilePreview`、`ReadOnlySourcePreview`，经共用 `ReadOnlyWorkspaceFiles` 组合 | 授权只读数据源；管理页不新增输入引用入口 |
| 技能管理与调用 | `WorkspacePageContainer` 的受控内容宽度、`ThemeSearchSection` 的两列紧凑目录，原生 Toggle/Popover/Menu/Dialog/Toast；文件详情按需使用满高工作区，调用继续使用 `$` 候选、标签及说明预览 | 信息结构及直接分配流程参考 Skills Manager；卡片仅保留名称、简述和直接分配，版本及内部／外部权限沿用 AutoOps，不引入桌面 preset |
| 业务操作 | `AddProjectToMachineDialog`、设置弹窗的 `DialogHeader/Panel/Footer`，原生 `Select`、`Menu`、`Checkbox` | 公开 Git 导入、脱敏、逐项复核、部署包与任务取消 |
| 响应式 | 原生文件面板分栏、窄屏目录/预览切换、菜单焦点边界 | 缩小窗口后操作仍可达，弹窗内容滚动且底部动作可见 |

整页验收同时检查浅深色、1440px 桌面、390px 触屏和短窗口。覆盖长路径、长标题、版本切换、文件内容、菜单及弹窗、键盘关闭与焦点恢复；检查滚动容器内部实际宽度和右侧按钮边界。不得靠隐藏业务动作、权限校验或未完成流程取得视觉上的一致。前端重构应保留原版本生成、复核发布、下载和任务取消接口及其失败反馈。

## 新增模块与插件的结构规范

2026-10-23，用户确认顶部项目与模块导航的实际效果，将其作为全项目后续开发的强制结构基线。参考实现为 `97e57b23` 中的 `ProjectAreaTopbar`、`AppSidebarLayout` 及工作区、部署独立页面；后续沿用这些共享模块，不复制一套插件专属页面壳。T3 Code v0.1.1 仍是唯一组件与交互参考，顶部业务编排属于 AutoOps 适配，不将其声称为上游已有页面。本节适用于内置业务模块、MCP 管理及插件可视化页面；旧原型图或其他文档与此冲突时，以本节的结构要求为准。

| 范围 | 必须遵循的结构 |
| --- | --- |
| 全局壳 | 复用全宽 `52px` 顶部栏与其下满高内容区。顶部统一选择授权项目；业务页面不再添加一套品牌栏、项目选择器或重复模块标题行。模块自己的贴边工具栏保留必要操作。 |
| 功能增长 | 桌面保留问答、工作区、部署发布三个常用入口，新增模块默认进入同一可搜索“更多功能”；不自动追加为常驻按钮，不新增全局纵向功能侧栏。只有明确调整产品常用入口时才改变顶部集合。 |
| 窄屏导航 | 复用当前响应式断点与同一“切换模块”搜索下拉，不为插件另写一套移动导航。当前项目与当前模块保持可见，长名称在控件内省略，菜单可滚动且不超出视窗。 |
| 模块页面 | 有可视化操作的模块使用共享壳内的独立路由，内容占满剩余宽高，列表、目录、预览与详情按 T3 原生面板分栏。左侧空间仅承载模块自己的内容；没有列表时不保留空侧栏或占位。 |
| 工具型插件 | 仅提供 Agent/MCP 工具的插件接入现有配置、授权和调用流程，不强制创建独立页面，也不为凑导航增加空页面。需要连接管理或业务操作时，再按同一模块结构提供页面。 |
| 操作与元数据 | 常用动作放模块工具栏；低频配置、详情和确认复用原生菜单、Dialog/Sheet。主要业务内容优先获得空间，不将整页改为卡片集合、常驻长表单或固定高度嵌入框。 |
| 共用组件 | 导航、主题、字体、工具栏、菜单、弹窗、加载与错误沿用同一 T3 组件及状态流程。第三方插件的独立后台模板不得直接带入工作台；适配其业务数据和能力，不引入第二套设计系统。 |

模块入口必须从同一授权功能定义生成，桌面、更多功能与窄屏不能维护互相不一致的入口清单。新增定义须明确稳定 ID、中文名称、图标、路由或所接入的工具、作用范围、启用条件与所需权限；工具声明不等于必须增加页面导航。这是后续接入要求，不表示当前已完成独立插件 SDK、市场或动态安装能力。只开放已经具备真实业务闭环的入口，不展示假连接、假任务或占位按钮。停用或撤权后，入口、新调用及直接链接都必须按当前权限处理；历史结果仍按既有阅读权限保留。

项目级模块使用顶部统一上下文，环境、版本及其他业务范围在模块内按需选择；全局设置须明确其全局作用域，顶部项目仅保留返回业务区域的上下文，不因项目变化改写全局配置或账号操作的归属。切项目、切模块只改变浏览位置，不能重绑已开始的对话、任务或部署，也不能停止后台执行。待提交动作在提交前重新核对原绑定和当前授权，不把旧项目输入带入新项目操作。草稿与查看状态按用户、项目和资源隔离，深链以资源真实归属校验；刷新、前进后退、设置返回和权限失效时都不能静默切到其它项目操作。

固定控件必须区分全局顶栏与模块内部坐标。聊天面板、插件浮动工具栏和移动侧栏不能覆盖顶部项目或模块入口；局部 absolute 控件不能因全局顶栏重复偏移。沿用当前共享布局及固定控件偏移机制，不以提高层级、隐藏必要按钮或硬编码新的页面高度掩盖冲突。

交付验收须覆盖实际受影响的整页和流程：浅深色、1440px 桌面、390px 窄屏、600px 短窗口、长名称及长数据、内部滚动、模块搜索、键盘与 Escape 焦点恢复、触屏真实点击命中；另查授权/停用及直接链接、跨项目状态、刷新/历史/返回和模块切换后的任务绑定。记录复用来源、业务差异、已测与未测范围。新增模块不能通过挤占全局导航空间或隐藏已闭环功能来满足验收。

## 技能中央库适配

技能模块沿用上述共享顶部壳，入口在“更多功能”及窄屏“切换模块”，不增加常用按钮或全局侧栏。导入和刷新位于模块工具栏，避免再占一行页面标题。中央库与助手分配标明全局作用域；项目技能直接使用顶部项目，不新增页面级项目选择。保留用户确认的技能卡片及卡片直接分配，卡片是技能集合的主要内容，不是通用后台装饰。项目切换关闭未提交弹窗并隔离查看状态；已经提交的操作仍绑定原目标。

技能中央库优先显示完整卡片集合及真实分配状态，文件详情按需进入。卡片上的助手按钮点击分配、再次点击取消；项目入口在同一卡片展开带搜索的目标列表。快捷操作不得误触文件详情，不得自动更新已有分配版本或扩大外部权限；新分配明确默认仅内部。取消项目单独分配会恢复助手继承，应在项目列表内解释。加载反馈放在正在操作的目标，成功状态以服务器返回为准，冲突刷新后由用户重新操作。详情返回须恢复原卡片焦点和滚动位置。

技能卡片的来源不能仅以外壳 class 一致为依据：整页沿用 T3 设置页的内容宽度与分组节奏，工具栏合并范围和搜索，名称、简述、分配区构成三个主要层级。助手与项目标签和控件同行，使用原生紧凑 Toggle；不重复展示正常“可分配”徽标、版本哈希、来源和工作区说明。未就绪/停用状态必须可见，完整原因和版本按需查看。新增分配的默认范围通过明确的说明入口和操作反馈表达；成功使用原生 Toast，错误保留就地反馈，不让常驻通知推移目录。触屏实际点击高度、长标题、键盘与焦点仍须验证。

在项目分配浮层或管理弹窗内连续修改时，先呈现服务端返回的选中/列表状态，关闭当前浮层后再显示最后一次成功 Toast，避免通知争夺 Esc 关闭顺序。保留现有错误与加载反馈；不得用测试连按 Esc 或等待通知消失来掩盖弹层键盘问题。

## Agent 问答流程

优先复用 `ChatView`、`components/chat/`、原输入编辑器、虚拟时间线、Markdown、命令与投影，不再实现平行的聊天状态机。

1. 输入、附件、资料上下文、斜杠命令与快捷键使用原输入区结构；支持中文输入法，组合输入期间不能误发送。发送后清空、失败恢复、草稿与暂存按原流程处理。
2. 执行中沿用“引导当前执行”和“排队到下一轮”的原操作语义与能力判断；停止、队列编辑、取消、暂存和恢复保持各自状态。没有后端能力时显示真实限制。
3. 等待、运行、工具调用、提问、授权、完成、失败和中断由真实事件驱动。只展示模型实际返回且允许公开的推理摘要；不伪造思考过程，不把工具结果改成虚假的推理。
4. 工具活动沿用原聚合、折叠、详情与结果展示规则，资料读取走同一工具项；不另加重复进度卡、重复完成提示或内部实现说明。
5. 流式正文沿用原增量渲染、Markdown 和代码高亮。历史沿用分页、虚拟化与懒加载；不为中文化或视觉效果增加全量重绘。
6. 在底部时自动跟随，向上阅读时保持位置；新内容提示与回到底部使用原控件。展开工具、加载旧记录、切换对话与重连都要保住阅读位置。
7. 已开放的复制、重试等动作沿用原位置、显隐和确认时机。精简版不开放新计划、分支与历史回退，旧记录仍可阅读；恢复这些能力时必须同步原生权限、菜单、快捷键与设置。
8. 刷新与断线恢复使用原游标、事件去重和持久状态。不得显示假成功、自动重复执行或丢弃排队和草稿。

## 验收要求

按改动范围检查真实页面：设置入口与搜索、导航、输入、菜单、弹窗、焦点恢复、键盘和中文输入。覆盖浅/深色、系统主题、390px 窄屏、常规桌面、长中文及减少动态效果。对话变动另查运行中输入、队列/停止、向上阅读、回到底部、刷新与重连；不得用截图代替时序验收。

执行相关类型检查、构建及必要的定向测试，保留第三方许可。记录已测和未测的边界；不能因代码迁入就声称全部上游能力均已验证。UI 静态资源发布优先避免重启活动执行进程，不触碰用户历史数据。
