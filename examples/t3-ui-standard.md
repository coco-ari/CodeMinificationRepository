# T3 UI 统一规范与开发提示词

本规范用于 AutoOps 后续所有页面、交互原型和新增功能。自本次切换起，T3 Code 是唯一 UI 与 Agent 交互主参考，替代早期 Solid Glass 材质与强制 Radix 的要求。业务需求仍由项目需求文档决定；不能因为上游是编程工具，就给用户增加无关的仓库、终端或模型配置步骤。

代码组织、服务端数据/草稿隔离、缓存与前端测试遵循 [工程与 AI 协作规范](engineering-standard.md)。本文件只维护视觉与交互基线，避免重复规定状态和模块边界。

## 复用与全项目规范

先遵循 [项目全局规范](../AGENTS.md) 与 [后端架构与模块规范](backend-standard.md)。执行 AGENTS.md 的三步顺序，以当前分支为唯一功能基线。规范完成后再优化全部现有模块，保留已有入口、业务流程、真实状态、授权边界及统一交互；新增功能放在后续。内部实现可以替换，不能因统一风格遗漏操作或清理正在使用的数据。

前端不重复造轮子：先复用锁定 T3 的完整模块，再组合原生组件；其他成熟开源能力仅补业务缺口，不能引入另一套页面壳或设计系统。后端也优先复用成熟执行器、协议客户端与连接实现，通过模块公共接口适配。自研前说明现有能力不适用的具体缺口。

权限由后端统一裁决并投影为 capabilities，页面不散落独立角色判断；同一功能注册表同时支撑桌面、窄屏、深链与停用状态。后台合同改变时同步修改客户端，不保留旧新双轨实现。

## 操作简洁性

同步源码、刷新和默认脱敏生成等常规操作直接执行，不增加重复确认。需要输入才打开表单，低频规则放次要菜单；删除、对外发布和权限变更仍按实际影响保留必要确认。默认界面只显示有用内容、主要动作和当前状态，去掉重复的原理说明、修订号及常驻成功提示。

当前资料页采用已确认的紧凑布局：标题、上传和同步同行，任务记录、新建对话、目录及当前文件操作收进原生菜单；根目录不重复显示“当前资料”路径横栏，子目录路径与搜索共用文件工具栏。保留目录处的一次刷新，同时更新资料状态；打开文件后沿用左侧预览、右侧目录，窄屏只显示当前面板。未选中文件时不常驻空预览栏，异常与恢复提示仍在所属区域按实际状态显示。

请求收据、幂等标识和恢复策略由系统处理。网络异常后自动查询已有结果，页面最多提供一个“重试”入口；已确认失败才允许新请求，未知结果不能伪装失败或重复执行。成功用原生 Toast，失败用所属区域的简短原因；历史异常保留在任务记录，不持续把已恢复的页面标红。组合 Alert 必须使用正文/标题/操作槽位，不能将业务容器直接放入图标位置。

## 局部异常与公共框架

业务模块加载、空态、请求失败或渲染异常均留在所属内容区，保留公共顶栏、侧栏容器和可用的模块切换。只在对应区域展示重试或不可用原因，不以整页刷新、重建页面壳或空列表掩盖失败。共享身份/权限失效时统一提示并限制相关操作，不保留越权的缓存内容。

后台任务状态由任务本身拥有；切模块、关闭详情或局部重试不取消任务、不重复提交。故障提示沿用 T3 原生层级与控件，保留故障、恢复及当前运行状态的区别。具体错误边界、异步清理和缓存规则由工程规范维护。

## 固定参考与实现边界

- 源码基线：[T3 Code](https://github.com/pingdotgg/t3code/tree/fe27e8e3dc12dcbb108e9a28fd9b8cb65f34ae92)，v0.1.1，提交 `fe27e8e3dc12dcbb108e9a28fd9b8cb65f34ae92`。以本仓库 `vendor/t3code/.autoops-source/manifest.json` 和文件清单核对来源，不能静默改用最新版。
- 前端采用 T3 的 React、TypeScript、Tailwind CSS 4、TanStack Router 和 React Compiler。组件以 `vendor/t3code/apps/web/src/components/ui/` 为准，shadcn 配置为 `base-mira`、Zinc、Lucide；原生交互底层为 Base UI。组件注册源不等于另一个设计系统。
- 复用优先顺序：已有 T3 模块 → T3 组件组合/变体 → 按同一模式补充缺失业务组件。新增按钮、菜单、选择器、对话框、提示等不得在业务页另造一套。
- 技能管理的信息结构和分配操作按用户确认的 Skills Manager `MySkills`／`SyncDots` 流程适配：技能卡片直接切换助手，在同一技能上管理项目。视觉及基础交互组件仍采用 T3；不照搬 Skills Manager 的桌面材质、preset 或安装路径设置。
- 旧验证版本中的 Radix 兼容层仅是历史实现事实，不约束新产品设计。重建页面使用锁定 T3 的原生 Base UI 组件，验证焦点、键盘、浮层与触屏流程，不为延续旧组件签名保留第二套实现。
- AutoOps 登录、身份、项目/环境、共享权限、资料、报告与执行工具接入统一业务服务。新产品接口及数据模型按后端规范设计；UI 不自行改写授权、固定输入、执行目标或用户选择的模型配置。
- 当前 Demo 的开放范围以 [精简版能力边界](agent-demo-lite-profile.md) 为准：对已开放模块复用完整原生流程，并不要求把 T3 所有功能都展示出来。收起的模块保留源码与历史读取能力，后续统一通过产品能力配置恢复，禁止零散加回入口。

## 视觉与布局

风格是克制、紧凑、内容优先的桌面工作工具。沿用 T3 页面骨架、主内容列、贴边工具栏、菜单模式和信息密度；全局项目与模块入口按下文的 AutoOps 顶部导航组合实现。不要增加大面积营销渐变、厚重玻璃卡片、巨型圆角、每行阴影或重复状态徽标。

| 项目     | 统一做法                                                                                                                                                                                 |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 颜色     | 使用 `background`、`foreground`、`muted`、`border`、`accent`、`primary`、语义状态等现有主题 token，不在业务页硬编码另一套色板。默认 T3 Code 浅色，保留用户已选主题、深色和跟随系统设置。 |
| 主题来源 | `apps/web/src/index.css`、`themePalette.ts` 与 `packages/shared/src/themePalettes.ts`。不再导入旧 Solid Glass 全局覆盖；T3 自带的 `surface-glass` 仍按原组件使用。                       |
| 字体     | 使用 `--font-sans`、`--font-mono` 和外观设置中的字号变量，中文使用系统字体回退。代码保留等宽字体，不全局覆盖用户字体设置。                                                               |
| 几何     | 优先用原组件变量；基线 `--control-radius: .5rem`、顶部 `52px`、对话正文最大宽 `46rem`、详情栏 `17.5rem`。这些是复用原布局的参考，不是给所有业务容器强加固定宽高。                        |
| 间距     | 沿用现有 Tailwind 间距与 `--workspace-gutter`，桌面与窄屏按原断点处理；不通过大量空白营造层次。                                                                                          |
| 控件     | 选择组件已有 `variant`、`size`、`density`。外观由组件拥有，调用处只布置布局；通用新外观先成为共享变体。                                                                                  |
| 面板     | 设置用原设置行/分组，清单用连续列表或表格，详情按需展开；不把每个字段包装成独立卡片。                                                                                                    |
| 文案层级 | 一层标题与操作区；辅助信息使用弱化文字，真实业务状态单独表达。保留表单帮助与错误，不增加泛化副标题。                                                                                     |
| 动效     | 保留 T3 动作时机与短过渡，默认跟随系统的减少动态效果设置。外观中的“界面动效”可选择跟随系统、开启或关闭；显式开启时可独立于系统设置。CSS 与 JavaScript 使用同一有效偏好，后台与不可见动画仍暂停。 |

精简版对话侧栏复用 T3 原生 `slim` 单行变体，桌面沿用紧凑行高，触屏保留至少 44px 的点击高度。项目名称由全宽顶部项目选择器统一展示，会话行保留原项目图标与详情提示，不再另加全局范围标题或项目选择。运行、等待回复、失败、未读及置顶等真实状态必须保留；草稿、搜索、菜单、焦点和拖拽继续使用原组件流程。搜索命中的真实内容摘要按需保留，不为统一行高丢失检索证据，也不通过缩小全局字号提高密度。长标题和草稿必须在侧栏视窗内真实省略，不能撑宽滚动内容或裁掉右侧状态和操作。更多操作在悬停、键盘聚焦与触屏下可达；菜单应沿用当前浮层的焦点边界，关闭后恢复入口焦点。

紧凑行的状态与操作沿用 T3 尾部区域复用方式，不把透明的更多或删除按钮再作为独立列挤占标题。桌面悬停与键盘聚焦切换同一尾槽中的展示，标题宽度保持稳定；触屏保留同时可见的状态与操作，并让实际触区留在尾槽及侧栏视窗内。可交互的提醒状态不得因切换操作而留下不可见的焦点目标。未发送草稿的标记与删除入口遵循同一规则，继续使用原有操作组件和处理流程。

## 问答公共框架与跨模块一致性

2026-10-23，用户明确要求先统一公共框架：全站以当前问答区域实际使用的主题和工作台外壳为基准。切换模块时，导航、侧栏、内容起点和面板边界应连续稳定。本节收紧此前允许模块分别组合外壳的做法；与旧图、历史验收及“无列表时移除侧栏”等规定冲突时，以本节为准。T3 锁定版本及业务授权边界保持适用。

1. **共享外壳**：复用问答的 `AppSidebarLayout`、原生 Sidebar、`WorkspacePageHeader`、内容容器和主题变量。公共层统一全局顶栏、左侧模块面板、主内容头部、内容容器及按需辅助面板；模块通过公共区域提供内容，不复制自己的页面壳。 当前业务接口为 `apps/web/src/autoops/ModuleWorkspace.tsx` 的 `ModuleHeader` 与 `ModuleSidebar`：页面保留自身数据和操作归属，侧栏内容投影到公共原生容器；模块不得重新创建 `SidebarProvider` 或独立侧栏宽度状态。
2. **主题与尺寸**：沿用问答的背景、侧栏表面、分隔线、字体层级、间距、图标与控件状态。相同窗口及面板状态下，顶栏高度、侧栏宽度、内容起点、头部高度、折叠入口和固定操作位置一致。通用外观在共享组件维护，业务页只组合内容。
3. **模块侧栏**：问答承载对话，工作区承载当前文件/源码来源，部署承载服务，其他模块承载当前分类或列表。共用搜索、主要动作、列表行、选中态、滚动与底部公共入口的规则。不得把对话列表带入其他模块或另起全局纵向导航；空数据保留侧栏及其空态，不因切页或加载改变整体骨架。
4. **状态归属**：侧栏尺寸及用户展开偏好由公共层管理，模块切换不自动展开或收起；移动端选择具体资源后可按原生规则关闭抽屉。模块草稿、选中项、查看版本和滚动按用户、项目及资源分别恢复；切换不停止执行、不重绑任务、不串用其他项目数据。
5. **头部层级**：主内容使用统一头部，环境、版本、业务页签和动作按职责紧凑组合。低频操作放原生菜单、弹窗或详情。避免分别堆叠多行横栏、重复标题、重复配置、作用不清的刷新按钮和重复状态摘要；主要内容获得剩余空间。
6. **业务内容**：目录/预览、服务配置/日志、技能卡片等可采用适合业务的内部布局，共用容器表面、留白、空态及加载反馈。不要机械复制问答欢迎语或输入框。所有已接入操作、真实状态、错误和授权必须保留；尚未迁入的业务另列缺口，不以公共框架完成宣称业务整合完成。
7. **滚动与响应式**：全局顶栏与公共骨架稳定，各面板独立滚动，避免整页及多层容器同时争夺滚动。统一断点、抽屉、折叠、返回与焦点恢复；短窗口仍可操作，长名称和内部滚动不得挤出右侧动作。加载、错误与空态不改变框架边界。
8. **新模块**：技能库、我的电脑、设置以及未来 MCP/插件均接入同一公共框架和授权功能注册表，不携入第二套品牌栏、项目选择器、侧栏、主题或弹窗。工具型插件不强行增加页面。
9. **验收**：相同尺寸、主题及展开状态下连续切换问答→工作区→部署发布→技能库→我的电脑→设置，对照顶栏、侧栏、内容起点、头部、分隔线和固定控件。覆盖浅深色、1440px 桌面、390px 窄屏、600px 短窗口、空态/加载/错误、长数据、内部滚动、真实点击、Esc 和焦点恢复。提供同尺寸对照截图和实际切换结果，记录共享组件、业务差异及未覆盖项；单页截图不能代替跨模块验证。

## 内容呈现与 T3 原生质感

公共外壳按当前 AutoOps 框架保持稳定，内容区按锁定 T3 的组件组合、信息层级和操作节奏实现。框架一致与呈现一致分别验收；使用了 T3 按钮、颜色和圆角，不能证明页面已有 T3 的整体质感。本节是 AutoOps 对业务页面的落地约束，不声称 T3 上游已有部署发布、工作区版本或权限管理页面。

### 参考来源与页面类型

实现前给出“上游参考模块 → 组件及变体 → 业务适配”的对应关系。`vendor/t3code` 中部分文件已经中文化或适配，不能仅凭文件位置认定与原版一致；必要时按[导入清单](../vendor/t3code/.autoops-source/files.jsonl)核对固定提交的原始文件。只比较影响本次呈现的差异，不为了追求文件哈希一致撤销授权、中文化、可访问性或已确认的框架适配。

| 页面部分 | T3 参考 | 组合要求 |
| --- | --- | --- |
| 侧栏与资源行 | [Sidebar](../vendor/t3code/apps/web/src/components/ui/sidebar.tsx)、问答 `slim` 行的密度与尾部动作模式 | 模块保留自己的资源数据；统一搜索、行高、图标、选中态与操作槽位，不复制会话状态逻辑 |
| 文件、源码和日志工作台 | [文件面板工具栏](../vendor/t3code/apps/web/src/components/files/fileSurfaceChrome.tsx)、[FileBrowserPanel](../vendor/t3code/apps/web/src/components/files/FileBrowserPanel.tsx)、原生预览和 ScrollArea | 满高、贴边、连续内容；保留已有目录/预览分栏，减少外围重复业务栏，不重写目录树、代码预览或滚动机制 |
| 配置与权限设置 | [settingsLayout](../vendor/t3code/apps/web/src/components/settings/settingsLayout.tsx) 的 `SettingsSection` / `SettingsRow`、[SettingsGroup](../vendor/t3code/apps/web/src/components/settings/SettingsGroup.tsx)、[WorkspacePageContainer](../vendor/t3code/apps/web/src/components/WorkspacePageContainer.tsx) | 使用受控内容宽度、分组、主标签与辅助说明、同行值或操作；复用呈现组合，业务权限和数据仍归业务模块，不接入无关的个人设置字段 |
| 技能及其他资源目录 | [ThemeSearchSection](../vendor/t3code/apps/web/src/components/settings/ThemeSearchSection.tsx) | 复用紧凑卡片、两列节奏与底部动作层级；技能的助手和项目直接分配属于已确认业务差异，必须保留 |
| 导入、发布及确认弹窗 | [AddProjectToMachineDialog](../vendor/t3code/apps/web/src/components/AddProjectToMachineDialog.tsx)、原生 Dialog / AlertDialog | 标题、主体、动作区分工清楚；重点呈现对象、范围、版本和后果，技术校验信息按需展开 |
| 状态与提示 | 原生 Badge、Alert、Collapsible、Toast；聊天提示参照 [ComposerBanner](../vendor/t3code/apps/web/src/components/chat/ComposerBanner.tsx) | 沿用语义、密度和槽位组合；业务任务可以有最小专用摘要，不能搬入聊天专用状态机或另造通用进度系统 |

T3 文件工作台、设置页和目录页有不同的宽度与留白，不能把它们全部做成贴边表格，也不能全部塞入居中卡片。工作区和日志使用剩余空间；配置内容采用 `WorkspacePageContainer` 的已有宽度档；目录卡片采用原生网格。继续复用原生文件预览，不把空目录或未选文件时的留白误判为必须增加摘要卡片。

### 信息层级与操作组织

1. **每层只表达一个定位职责**。公共页头识别当前业务对象；上下文工具栏承载范围、业务视图和常用动作；文件面包屑表达路径；任务摘要表达本次执行。相邻横栏不得再次完整复述同一版本名、环境、时间、状态和操作。路径需要根目录名称时保留面包屑，优先消除额外的同名摘要栏。
2. **限制业务横栏堆叠**。桌面默认稳定视图，公共页头下至多保留一行紧凑业务工具栏；发布任务可再保留一处紧凑结果/运行摘要。不要给服务元数据、页签、任务选择、阶段和来源各建一条常驻横栏。文件自身的路径/工具栏继续按原模块使用；阻断性错误与用户主动展开的详情可以增加内容，但不能以固定高度裁切信息。窄屏可按语义换行或进入菜单。
3. **操作归属清楚**。页头负责当前对象的主动作，面板工具栏负责当前面板的筛选、搜索与刷新，行内操作针对该行。一个上下文默认只有一个主色实心主动作；并列次要操作使用现有 `ghost`、`ghost-muted` 或 `outline` 变体。刷新当前目录与刷新版本列表是不同动作时必须标明范围；相同范围只保留一个入口。
4. **选择器区分导航与填写**。环境、查看版本、任务等上下文选择使用适合工具栏的原生尺寸和变体，由父容器约束宽度并处理长文本；不得直接继承表单 `w-full`，把短选项铺满宽屏。确实需要输入/编辑的字段才采用表单布局；不能因此禁止 T3 原生有边框选择器。页签/分段控件按同级视图使用，不层层嵌套胶囊背景或每组另占一条横栏。
5. **状态有层级且不混淆对象**。详情中将同一次任务的状态、失败原因、恢复结果归并到一个摘要，以状态文案、图标和必要的语义色区分；阶段详情按真实顺序和结果展开，不能仅平铺一串同色阶段名充当进度。失败且恢复成功不等于发布成功，恢复失败或结果未知必须明确。侧栏可保留资源摘要，选择器可保留辨认历史任务所需状态，详细日志保留原始证据，不为去重删除这些必要信息。
6. **来源和版本必须区分语义**。正在运行的版本与所选历史任务的来源可能不同，应分别标明“当前运行版本来源”和“本次任务来源”，不能用两个相同的“查看工作区来源”让用户猜，也不能为了简洁错误合并不同版本。机器 ID、完整哈希和清单内容保留复制、查看与校验入口，默认优先显示有意义的名称和可辨识版本。发布确认仍须清楚展示环境、目标、选定包/固定版本及影响。
7. **按任务组织配置**。部署配置按目标与站点、构建、验证与恢复等业务职责分组，权限按授权对象、范围和动作分组；使用原生设置行及对应表单/只读值。避免把内部 ID、构建参数、状态、帮助混成同一字号的全宽参数表，也不把每项设置套成独立卡片。

### 组件、密度与视觉层级

- **组件、变体、尺寸一起复用**。必须确认所选 `variant`、`size`、可用时的 `density` 以及父布局，不能只核对组件名。控件外观由组件拥有；业务调用处不得用 `className` 覆盖字号、内边距、高度、圆角、边框、背景或阴影。通用缺口在共享变体/槽位补齐，业务独有组合留在所属模块；遵循 [T3 Web UI](../vendor/t3code/docs/internals/web-ui.md) 的组合边界。
- **侧栏先用紧凑资源行**。普通分类/版本/服务导航默认单行，使用原生行尺寸、图标与尾部状态/操作槽位；桌面 `SidebarMenuButton` 默认行高为 `h-8`，这不是所有列表行的固定高度。确实需要第二行辨认对象时使用统一详情行变体，并说明保留的信息；不得所有行都常驻“名称＋正常状态＋数量＋时间”，或逐页用 `h-auto`、`py-*` 覆盖原生行。触屏至少 44px 的可点击范围、长名称省略和键盘操作继续满足原规范。
- **字号表达职责**。对象名称、主要配置标签和主要操作沿用原模块的 `text-sm` 等主层级，时间、数量、说明使用原有 `text-xs` 等辅助层级，源码/日志使用原生等宽字体及行距。不能把全页缩成小号灰字，也不能通过加大全局字号、字体加粗或修改用户设置修补局部层级。数值只是组件基线，应跟随用户字体及缩放偏好。
- **边界只划分真实区域**。原生表面、轻边框和分隔线用于容器边界、可操作分组或连续列表；同一工具栏内用间距组织，不给每一行摘要都加横线、独立底色或外框。T3 原生设置分组、目录卡片、弹窗保留自身圆角和阴影；不能为“统一”全部抹平或替换为同一套卡片。
- **正常状态克制，异常状态可见**。不在标题、侧栏、工具栏、选择器与正文连续重复同一绿色“可用”或红色失败徽标。持久故障放所属对象的一个稳定摘要，成功反馈优先用原生 Toast，不让通知反复推移内容。关键权限限制、阻断原因、运行状态和恢复异常不能只放在 Tooltip 或更多菜单里。
- **面板优先获得空间**。目录、预览和日志占满剩余可用高度，各自按原生方式滚动；低频参数和详细事件按需展开。操作、状态和日志持续更新时不得反复抬高工具栏或跳动内容起点。卡片及列表中的主要动作保持可预测位置，悬停、键盘与触屏下均可达。

### 呈现验收

先锁定同一主题及模式、字体/字号偏好、浏览器缩放、窗口尺寸、侧栏状态和有代表性的数据，再对照原生参考。仓库中的中文外观设置与问答可作已集成参考，但不能冒充完全未经修改的上游页面；原始样式以固定提交及校验清单为准。

| 检查项 | 通过条件 |
| --- | --- |
| 框架与内容分别检查 | 顶栏、侧栏、公共页头几何稳定；同时检查内容起点、业务横栏数、文字层级、控件宽高、动作位置与分隔线，不能只测 `52px` 顶栏和无横向溢出 |
| 主体可见空间 | 1440×600 的默认稳定视图中，文件/预览/日志视口原则上占公共内容页头下方可用高度的至少 60%；记录实测尺寸。必要阻断信息或主动展开详情可例外，须说明原因，不能隐藏错误、缩小字号或裁掉动作达标。这是 AutoOps 的内容优先目标，不是 T3 上游固定像素规范 |
| 真实数据 | 发布覆盖运行、成功、失败且恢复成功、恢复失败/未知；工作区覆盖目录、选中文件、长路径、无数据与无权限。未能实测的状态明确列出，不能把演示数据当作后端闭环证据 |
| 资源与动作 | 当前运行版本、本次任务、源码包及其来源可辨认；正常状态无无意义重复；下载、配置、发布、恢复和直接分配等已闭环功能保持可达 |
| 窄屏与短窗口 | 检查 390px 宽和 600px 高，标题不能被按钮挤到无法辨认；次要动作进入原生菜单，核心目标、异常和主动作可见。另验真实触屏/粗指针的触区，缩小桌面视口不能代替触屏验收 |
| 浮层与阅读状态 | 检查下拉、确认弹窗、返回、Esc、焦点恢复、长内容滚动、阅读日志时更新和主题切换；截图只证明静态呈现，不能代替交互与时序验证 |
| 参考与证据 | 交付记录上游参考、实际业务差异、同条件截图和未测范围；截图前等待目标页面内容及字体稳定，不能把路由切换中的上一页残留当作参考或最终结果 |

## 整页统一与工作区页面

开始实现前，先确定最相近的 T3 完整模块及其布局、操作入口与状态流程。风格统一包含页面骨架、分栏、工具栏、密度、状态反馈、滚动、响应式和键盘焦点；只使用相同按钮与主题不能视为完整适配。没有直接对应的业务页面时，组合原生模块，并明确业务差异，不另套通用后台模板。

项目与模块导航统一放在全宽 `52px` 顶部栏，不占用左侧内容列。项目下拉只列授权项目，桌面宽度随名称收紧并设最大宽度，长名称省略；项目与模块之间使用原生分隔线。桌面“问答、工作区、部署、技能库”四个常用模块使用 T3 原生 `ToggleGroup`，其后紧邻“更多”的可搜索 `Combobox`，仅列已授权的低频模块，不重复常用入口。进入低频模块后入口显示当前模块名称；无低频模块时不显示空菜单。窄屏将全部已授权模块合并为“切换模块”，显示当前模块名称。设置、外观、归档与退出继续由侧栏底部和设置页提供，不混入模块菜单。常用按钮、更多功能和窄屏菜单来自同一授权功能注册表，当前模块列出已闭环的问答、工作区、部署、技能库，以及开启客户接入后的“我的电脑”，新产品部署入口及动作按服务端能力授权展示，不在页面写死单一角色。未来 MCP、插件完成权限、数据和操作闭环后通过同一注册表加入，当前不展示未实现的占位入口。

各模块使用独立路由，内容填满顶部栏下的剩余高度，不把部署页嵌入工作区分类，也不重复增加页面内项目选择。左侧仅承载当前模块自己的会话、文件或服务列表：问答保留原生紧凑会话列表，工作区与部署复用同一模块侧栏，分别提供目录和服务列表，不常驻会话列表。复用 `WorkspacePageHeader`、项目 `Combobox`、原生 `ToggleGroup` 及满高内容面板组合；这是 AutoOps 业务导航适配，不声称上游已有相同顶部模块或部署页面。

工作区管理采用文件工作区布局，主要内容使用剩余高度。内部/外部范围与常用操作位于贴边工具栏，不提供日常工作区历史版本选择，窄屏将次要动作收入原生菜单。内部与外部区域共用文件目录和预览；部署页独立提供服务发布、源码包及所选清单预览，包独立固定服务关联仓库的 Git 提交，不默认包含上传资料。版本标识、哈希与来源等元数据按需查看，导入、脱敏、人工复核和任务详情通过原生弹窗操作。不得把管理页做成纵向表单集合，再嵌入带卡片边框和固定高度的文件浏览器。

项目为全局浏览上下文，环境与版本仍按各业务选择；已开始的对话和发布任务保持原绑定。切项目/区域只导航，不能取消执行、携带旧项目输入到新草稿或更换待确认发布的包。按用户与项目恢复草稿、查看版本、目录与文件、部署目标和任务；原生对话深链以实际归属为准，页面深链校验项目和版本权限。无效项目显示不可用，不回退到其它项目执行操作。设置页同样显示顶部项目选择；设置内切项目留在当前设置页，返回时在当前项目下恢复原业务区域，部署权限不足时返回工作区，不向旧会话路径拼接新项目。刷新、前进后退与跨区域来源跳转必须保持相同身份。

| 场景 | 必须复用的模块或模式 | AutoOps 适配边界 |
| --- | --- | --- |
| 全局项目与模块导航 | `WorkspacePageHeader`、项目 `Combobox`、原生 `ToggleGroup`、可搜索 `Combobox` | 全宽 `52px` 顶栏；同一授权功能注册表；窄屏合并模块入口 |
| 页面与工具栏 | `WorkspacePageHeader`、`SidebarInset`、`files/fileSurfaceChrome` | 项目、内部/外部资料范围、源码同步与外部发布状态 |
| 目录与内容 | `FileBrowserPanel`、`AttachmentFilePreview`、`ReadOnlySourcePreview`，经共用 `ReadOnlyWorkspaceFiles` 组合 | 授权只读数据源；管理页不新增输入引用入口 |
| 技能管理与调用 | `WorkspacePageContainer` 的受控内容宽度、`ThemeSearchSection` 的两列紧凑目录，原生 Toggle/Popover/Menu/Dialog/Toast；文件详情按需使用满高工作区，调用继续使用 `$` 候选、标签及说明预览 | 信息结构及直接分配流程参考 Skills Manager；卡片仅保留名称、简述和直接分配，版本及内部／外部权限沿用 AutoOps，不引入桌面 preset |
| 业务操作 | `AddProjectToMachineDialog`、设置弹窗的 `DialogHeader/Panel/Footer`，原生 `Select`、`Menu`、`Checkbox` | 公开 Git 导入、脱敏、逐项复核、部署包与任务取消 |
| 响应式 | 原生文件面板分栏、窄屏目录/预览切换、菜单焦点边界 | 缩小窗口后操作仍可达，弹窗内容滚动且底部动作可见 |

整页验收同时检查浅深色、1440px 桌面、390px 触屏和短窗口。覆盖长路径、长标题、版本切换、文件内容、菜单及弹窗、键盘关闭与焦点恢复；检查滚动容器内部实际宽度和右侧按钮边界。不得靠隐藏业务动作、权限校验或未完成流程取得视觉上的一致。前端重建须实现版本生成、复核发布、下载和任务取消的业务语义及失败反馈；接口使用新的统一合同，不保留旧接口兼容。

## 新增模块与插件的结构规范

2026-10-23，用户确认顶部项目与模块导航的实际效果，将其作为全项目后续开发的强制结构基线。参考实现为 `97e57b23` 中的 `ProjectAreaTopbar`、`AppSidebarLayout` 及工作区、部署独立页面；后续沿用这些共享模块，不复制一套插件专属页面壳。T3 Code v0.1.1 仍是唯一组件与交互参考，顶部业务编排属于 AutoOps 适配，不将其声称为上游已有页面。本节适用于内置业务模块、MCP 管理及插件可视化页面；旧原型图或其他文档与此冲突时，以本节的结构要求为准。

| 范围 | 必须遵循的结构 |
| --- | --- |
| 全局壳 | 复用全宽 `52px` 顶部栏与其下满高内容区。顶部统一选择授权项目；业务页面不再添加一套品牌栏、项目选择器或重复模块标题行。模块自己的贴边工具栏保留必要操作。 |
| 功能增长 | 桌面保留问答、工作区、部署、技能库四个常用入口，新增模块默认进入同一可搜索“更多功能”；不自动追加为常驻按钮，不新增全局纵向功能侧栏。只有明确调整产品常用入口时才改变顶部集合。 |
| 窄屏导航 | 复用当前响应式断点与同一“切换模块”搜索下拉，不为插件另写一套移动导航。当前项目与当前模块保持可见，长名称在控件内省略，菜单可滚动且不超出视窗。 |
| 模块页面 | 有可视化操作的模块使用共享壳内的独立路由，内容占满剩余宽高，列表、目录、预览与详情按 T3 原生面板分栏。左侧空间仅承载模块自己的内容；没有数据时保留公共模块侧栏与空态，框架边界不跳变。 |
| 工具型插件 | 仅提供 Agent/MCP 工具的插件接入现有配置、授权和调用流程，不强制创建独立页面，也不为凑导航增加空页面。需要连接管理或业务操作时，再按同一模块结构提供页面。 |
| 操作与元数据 | 常用动作放模块工具栏；低频配置、详情和确认复用原生菜单、Dialog/Sheet。主要业务内容优先获得空间，不将整页改为卡片集合、常驻长表单或固定高度嵌入框。 |
| 共用组件 | 导航、主题、字体、工具栏、菜单、弹窗、加载与错误沿用同一 T3 组件及状态流程。第三方插件的独立后台模板不得直接带入工作台；适配其业务数据和能力，不引入第二套设计系统。 |

模块入口必须从同一授权功能定义生成，桌面、更多功能与窄屏不能维护互相不一致的入口清单。新增定义须明确稳定 ID、中文名称、图标、路由或所接入的工具、作用范围、启用条件与所需权限；工具声明不等于必须增加页面导航。这是后续接入要求，不表示当前已完成独立插件 SDK、市场或动态安装能力。只开放已经具备真实业务闭环的入口，不展示假连接、假任务或占位按钮。停用或撤权后，入口、新调用及直接链接都必须按当前权限处理；历史结果仍按既有阅读权限保留。

项目级模块使用顶部统一上下文，环境、版本及其他业务范围在模块内按需选择；全局设置须明确其全局作用域，顶部项目仅保留返回业务区域的上下文，不因项目变化改写全局配置或账号操作的归属。切项目、切模块只改变浏览位置，不能重绑已开始的对话、任务或部署，也不能停止后台执行。待提交动作在提交前重新核对原绑定和当前授权，不把旧项目输入带入新项目操作。草稿与查看状态按用户、项目和资源隔离，深链以资源真实归属校验；刷新、前进后退、设置返回和权限失效时都不能静默切到其它项目操作。

固定控件必须区分全局顶栏与模块内部坐标。聊天面板、插件浮动工具栏和移动侧栏不能覆盖顶部项目或模块入口；局部 absolute 控件不能因全局顶栏重复偏移。沿用当前共享布局及固定控件偏移机制，不以提高层级、隐藏必要按钮或硬编码新的页面高度掩盖冲突。

交付验收须覆盖实际受影响的整页和流程：浅深色、1440px 桌面、390px 窄屏、600px 短窗口、长名称及长数据、内部滚动、模块搜索、键盘与 Escape 焦点恢复、触屏真实点击命中；另查授权/停用及直接链接、跨项目状态、刷新/历史/返回和模块切换后的任务绑定。记录复用来源、业务差异、已测与未测范围。新增模块不能通过挤占全局导航空间或隐藏已闭环功能来满足验收。

客户接入管理同样遵循新增模块规范：`/devices`「我的电脑」通过同一注册表进入更多功能及窄屏搜索，复用共享满高壳、紧凑设备列表和原生配对/详情/确认弹窗，不再在常规设置重复放置完整模块。设备属于当前账号的全局范围，顶部项目仅保留返回上下文；对话中的客户目录候选按当前项目授权筛选。模块关闭时隐藏入口，直接链接显示不可用，服务端仍拒绝新接入；不能靠页面隐藏放宽设备所有权或停止既有运行。

## 技能中央库适配

问答技能候选复用原生 `ComposerCommandMenu` 和目录刷新命令。加载、确认为空与失败必须区分；目录暂缺时自动重试，本次读取最多等待 30 秒，失败后仅提供“重试”，不得无限展示同步中。断网恢复可重新读取，重试不清空输入与已有标签。候选仍取当前授权技能与模型服务目录的交集；切项目、身份、范围或执行目标后取消旧等待，迟到结果不能恢复旧范围。

技能模块沿用上述共享顶部壳，桌面入口在常用模块，窄屏入口在“切换模块”，不另建全局导航，左侧复用公共模块侧栏，入口为“全部技能、助手分配、项目分配”，分别使用 Library、Bot、FolderGit2 图标，与其他模块保持相同尺寸和对齐。导入和刷新位于模块工具栏，避免再占一行页面标题。中央库与助手分配标明全局作用域；项目技能直接使用顶部项目，不新增页面级项目选择。保留用户确认的技能卡片及卡片直接分配，卡片是技能集合的主要内容，不是通用后台装饰。项目切换关闭未提交弹窗并隔离查看状态；已经提交的操作仍绑定原目标。

技能中央库优先显示完整卡片集合及真实分配状态，文件详情按需进入。卡片上的助手和当前项目按钮点击分配、再次点击取消；其他项目通过同一卡片的“更多项目”展开带搜索的完整目标列表。当前项目跟随顶部项目，卡片不再常驻列出其他项目；其他项目的单独分配数量保留在入口中，包含已停用分配，其状态在浮层内明确呈现。快捷操作不得误触文件详情，不得自动更新已有分配版本或扩大外部权限；新分配明确默认仅内部。取消项目单独分配会恢复助手继承，应在项目列表内解释。加载反馈放在正在操作的目标，成功状态以服务器返回为准，冲突刷新后由用户重新操作。详情返回须恢复原卡片焦点和滚动位置。技能名称仅在模块头部显示，详情工具栏合并返回、版本选择和异常状态；文件区域占满剩余高度。侧栏不常驻规则说明，分配规则收在说明入口，导入与分配弹窗仅保留当前操作需要的信息。外部范围的资料可见性提醒在选中外部工作区后显示。

技能卡片的来源不能仅以外壳 class 一致为依据：整页沿用 T3 设置页的内容宽度与分组节奏，工具栏合并范围和搜索，卡片头部复用 ThemeSearchSection 的 40px 中性图标底座，Sparkles 图标与全局技能入口一致，右侧集中名称与两行简述，更多菜单独立靠右。底部分配区用原生边框分隔，助手与项目标签和控件同行，使用原生 compact/outline Toggle，让未分配目标也明确可点；不重复展示正常“可分配”徽标、版本哈希、来源和工作区说明。未就绪/停用状态必须可见，完整原因和版本按需查看。新增分配的默认范围通过明确的说明入口和操作反馈表达；成功使用原生 Toast，错误保留就地反馈，不让常驻通知推移目录。触屏实际点击高度、长标题、键盘与焦点仍须验证。

在项目分配浮层或管理弹窗内连续修改时，先呈现服务端返回的选中/列表状态，关闭当前浮层后再显示最后一次成功 Toast，避免通知争夺 Esc 关闭顺序。保留现有错误与加载反馈；不得用测试连按 Esc 或等待通知消失来掩盖弹层键盘问题。

## Agent 问答流程

优先复用 `ChatView`、`components/chat/`、原输入编辑器、虚拟时间线、Markdown、命令与投影，不再实现平行的聊天状态机。

1. 输入、附件、资料上下文、斜杠命令与快捷键使用原输入区结构；支持中文输入法，组合输入期间不能误发送。发送后清空、失败恢复、草稿与暂存按原流程处理。
2. 执行中沿用“引导当前执行”和“排队到下一轮”的原操作语义与能力判断；停止、队列编辑、取消、暂存和恢复保持各自状态。没有后端能力时显示真实限制。
3. 等待、运行、工具调用、提问、授权、完成、失败和中断由真实事件驱动。只展示模型实际返回且允许公开的推理摘要；不伪造思考过程，不把工具结果改成虚假的推理。
4. 工具活动沿用原聚合、折叠、详情与结果展示规则，资料读取走同一工具项；不另加重复进度卡、重复完成提示或内部实现说明。
5. 流式正文沿用原增量渲染、Markdown 和代码高亮。历史沿用分页、虚拟化与懒加载；不为中文化或视觉效果增加全量重绘。
6. 在底部时自动跟随，向上阅读时保持位置；新内容提示与回到底部使用原控件。展开工具、加载旧记录、切换对话与重连都要保住阅读位置。
7. 已开放的复制、重试等动作沿用原位置、显隐和确认时机。精简版不开放新计划、分支与历史回退，旧记录仍可阅读；恢复这些能力时必须同步原生权限、菜单、快捷键与设置。
8. 刷新与断线恢复使用原游标、事件去重和持久状态。不得显示假成功、自动重复执行或丢弃排队和草稿。

## 验收要求

视觉改动必须同时满足“问答公共框架与跨模块一致性”和“内容呈现与 T3 原生质感”的验收要求。公共外壳测试通过不代表内容密度、控件组合和任务呈现通过；原生样式引用须区分固定提交源码与业务适配后的文件。

按改动范围检查真实页面：设置入口与搜索、导航、输入、菜单、弹窗、焦点恢复、键盘和中文输入。覆盖浅/深色、系统主题、390px 窄屏、常规桌面、长中文及减少动态效果。对话变动另查运行中输入、队列/停止、向上阅读、回到底部、刷新与重连；不得用截图代替时序验收。

执行相关类型检查、构建及必要的定向测试，保留第三方许可。记录已测和未测的边界；不能因代码迁入就声称全部上游能力均已验证。UI 静态资源发布优先避免重启活动执行进程，不触碰用户历史数据。
