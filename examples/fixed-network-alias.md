# 固定服务网络别名

Java 服务的固定网络别名属于部署位置，由中心保存并在每个任务中固定。业务镜像、源码版本和历史配置不会决定或移除这个名字。不同项目和环境应使用不同名称，例如 `solstandard-test-api`。

在部署目标「网络与存储」中填写已有共享 Docker 网络与固定别名；两个字段需一起填写。保存后，通过一次发布或重启应用。固定身份创建后不可修改或移除，需要不同身份时新建部署位置。静态站点无需此配置。

中心拒绝同一服务器、网络中的重复别名。Agent 在切换前再次检查实际容器，发现其他容器占用时停止任务，不修改该容器。网络必须已存在，Agent 不创建、替换或重启共享网络中的中间件。

- 发布：将固定别名加入 Compose 的网络配置。
- 重启：别名已存在时普通重启；尚未应用时，使用当前版本的镜像和已部署配置重建该业务容器。不会应用其他待发布配置，也不新增发布链节点。
- 回退和失败恢复：使用历史版本的业务配置，同时保留当前部署位置的固定网络身份。
- Agent 重启：任务保存的身份随任务记录恢复，不依赖临时 SSH 操作。

需要 Agent 1.6.0 的 `fixed-network-alias-v1` 能力。中心会拒绝给旧 Agent 创建此类任务，也会在领取时拦截能力降级。

## 已有服务切换顺序

1. 备份中心和 Agent 状态，等待任务结束，升级中心与 Agent。
2. 给所有被调用方保存固定别名；逐个通过平台重启应用。此时继续使用原来的调用地址。
3. 从调用方容器验证固定名称解析及只读 HTTP 访问。
4. 把调用地址写入项目对应环境的配置文件，提交并推送源码。
5. 移除部署配置中对应的 `--call.*.path` 参数，通过平台发布具体提交。
6. 核验实际运行参数、打包配置、调用链及中间件容器标识和启动时间。

测试环境使用 `test-middleware` 网络：

| 服务 | 固定地址 |
| --- | --- |
| API | `http://solstandard-test-api:10111/api` |
| 通信 | `http://solstandard-test-communication:10110/communication` |
| 管理 | `http://solstandard-test-manage:10112/manage` |
| 奖励 | `http://solstandard-test-reward:10115/reward` |

调用方必须在同一共享网络内。容器内自检继续使用 `127.0.0.1`；宿主机 Nginx 的回环上游保持原样。此方案不提供跨服务器名称发现。

## 验证

单元测试覆盖身份唯一性、不可变性、确认配置失效、旧 Agent 拦截、历史配置保持、普通重启与重建重启、别名冲突不操作中间件。`test/docker-integration.mjs` 在随机隔离网络中验证真实跨容器访问以及历史回退保留别名。

2026-10-17 本地验收：构建和类型检查通过；Linux 单元回归 116 项全部通过；浏览器回归通过，覆盖固定别名保存和多种屏幕宽度；真实 Docker 完整验收通过，包含新增固定别名访问、重启与历史回退场景，以及原有 Java/前端部署、断网恢复、源码重建和缓存额度检查。Windows 原生静态目录测试受符号链接权限限制，已在 Linux 容器中完整验证。
