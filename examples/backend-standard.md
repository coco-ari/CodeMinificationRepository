# 后端架构与模块规范

本规范记录 2026-10-23 已确认的新产品约束，适用于 AutoOps 全部后端模块和前后端公共合同。它是目标规范，适用于当前分支的模块优化及后续开发，不表示现有代码已经全部满足。项目全局规则见 [AGENTS.md](../AGENTS.md)，界面约束见 [T3 UI 规范](t3-ui-standard.md)。

## 复用与运行架构

通用开源调研与采用执行全局同名规则，不熟悉的功能先检索合格项目并比较方案，再确定实现范围。后端沿用已有代码和锁定上游，通过公开接口适配业务范围与权限；T3 原生会话与执行、协议客户端及已有资源连接能力仍由各自实现拥有，不另建平行实现。新增依赖的记录与版本管理遵循[工程规范](engineering-standard.md#配置依赖与维护成本)，不为了套用架构增加通用框架。

平台面向内部团队及获授权外部协作者，采用单中心模块化单体，首版按约 20 人、5 个并发 Agent 任务验证。使用 Node.js、严格 TypeScript 和 SQLite；不建设多租户、中心多副本、自定义角色设计器或任意插件安装平台。

中心应用通过宿主集成加载业务模块与 T3。业务模块独立于 T3 内部实现；反向代理不持有业务状态，耗时 Git、文件处理及构建任务使用受控执行进程。T3 原生存储由 T3 管理，不直接修改其会话、轮次和事件表。

按 2026-10-28 用户确认，当前 AutoOps 为开发测试实例，应用及测试数据可丢弃，可按需清理、重建或从空业务数据初始化，不要求迁移历史数据或保留旧 API、身份映射、双写及运行时兼容回退。此范围不包含源码、未提交改动、其他任务成果、外部服务及其数据；不因测试重建删除或覆盖这些内容。当前模块优化仍须保留产品功能，按[开发测试规范](development-test-standard.md)固定候选、完成必要本地检查与构建、验证实际健康及权限、生命周期、恢复能力，不等待 GitHub CI；不能把历史数据保留检查当作当前开发发版前置，也不能以重建代替功能验证。正式启用或生产环境的数据另按版本化升级、备份与恢复规范处理。新业务 HTTP 接口统一使用 /api/v1；T3 协议按锁定版本集成。

## 模块与唯一数据归属

以下是逻辑职责，不要求为每行创建独立进程、包或空目录。第二步按现有功能逐批归位；表中的职责不表示尚未实现的功能本轮必须补建。

| 模块 | 自有职责与数据 | 对外协作边界 |
| --- | --- | --- |
| 身份 | 账号、密码与登录会话 | 提供可信身份及账号状态；不决定项目业务权限 |
| 授权 | 角色模板、授权记录、权限决策 | 统一裁决动作与范围，生成 capabilities；不维护另一份项目/资源数据 |
| 项目与环境 | 项目、环境、成员、设置及归属关系 | 提供真实归属与成员事实；不保管工作区、发布或工具的内部状态 |
| 资料与工作区 | 当前资料、仓库来源与同步结果、任务资料输入、外部当前资料替换、持久化规则及更新结果 | 提供授权读取、本轮输入捕获和源码捕获；不要求会话选择工作区历史版本，不直接操作目录索引表 |
| 技能 | 中央库、不可变版本、助手与项目分配、停用和撤回 | 提供同一授权快照下的发现、预览与读取；执行仍交所属宿主 |
| 助手与会话业务 | 统一助手预设与项目分配、运行来源引用、会话业务绑定、共享范围、附件及成果访问规则 | 通过适配层调用 T3；不拥有轮次、队列及执行恢复状态 |
| 用户运行来源 | 设备所有权、配对、登记目录、能力与连接状态、提供者共享记录 | 作为助手运行来源；按提供者共享、项目分配和目录上限调用，不扩大平台模型或部署权限 |
| 资源与连接 | Server/MySQL/Redis、项目及环境绑定、连接能力和指标 | 提供受控连接操作及健康状态；不接管部署任务，不将凭证交给客户端 |
| 凭证 | 加密凭证、版本、引用、替换和撤销 | 按获授权服务端用途解析秘密；其他模块持引用，不复制明文配置 |
| 发布与部署 | 服务、部署位置、配置、源码包、任务、运行状态、版本及恢复 | 引用工作区提供的所选仓库提交与构建上下文，拥有源码包与发布状态；不直接写工作区或连接模块表 |
| 工具与插件接入 | 预置 MCP、工具声明、模块注册、启停及接入合同 | 适配已有应用服务，声明权限与健康状态；不重写各模块规则或创建第二套任务执行器 |
| 机柜 | 全局机柜业务、分配、二维码、照片与重置服务接入 | 通过独立服务合同接入，保持唯一主记录；与项目通过标识和受控同步关联 |
| 审计 | 必要操作记录与获授权查询 | 接受允许字段的事实，不反调业务服务；私有内容与凭证明文不得进入记录 |
| 通知与任务汇总 | 站内通知、获授权任务的查询投影 | 消费业务结果，允许独立失败与重建；不另建权限规则、不拥有源任务状态，查询仍经统一裁决 |

项目成员关系由项目模块拥有，授权记录由授权模块拥有；涉及两者的用例通过公开方法协调事务。物理文件存储可以共享，业务元数据和访问规则仍由所属模块负责。任务汇总是查询视图，不能成为另一份任务状态来源；机柜外部服务的数据也不能在中心形成另一份可独立修改的主记录。

模块内部按入口、应用服务、领域规则、基础设施分层。HTTP/RPC/MCP 入口只负责解码、调用和响应；业务规则集中在应用与领域层。跨模块只依赖公开合同，不直接读写对方表、不深层导入内部实现、不循环依赖。共同事务由应用流程协调，各模块仍通过自身接口写数据。

## 依赖与跨模块协作

模块可依赖权限、源码包、技能快照等其他模块的公开能力。先说明调用者、提供者、数据所有者及该依赖是否决定操作成败，再选择最简单的接口。工作区打包失败阻止依赖该包的发布，是正确的业务传播；无依赖的会话查询应继续可用。共享权限不可用时拒绝相关操作，不能为追求表面隔离绕过授权。

| 协作需求 | 默认实现与约束 |
| --- | --- |
| 同进程查询或必须取得结果的业务操作 | 直接调用公开应用服务；合同说明范围、结果、错误、幂等及取消语义，按需要注入窄端口 |
| 跨模块共同输入输出 | 复用纯合同及同源校验，不传可修改的内部存储或可随意调用的整个容器 |
| 耗时或需要恢复的业务操作 | 使用所属模块的既有任务和持久收据，查询同一个权威任务；不再包一层通用调度器 |
| 结果通知、界面刷新 | 复用现有订阅或事件；是否必须可靠送达决定是否持久化，不把核心业务条件藏进事件回调 |
| 外部协议或进程 | 在既有适配边界转换合同、权限和错误，配置资源预算 |

接口放在真实业务边界，不为每个函数新增抽象层。禁止在服务初始化或普通业务执行中改写注入对象的方法、原型或其他模块可变状态；协作锁、构建完成通知和数据读取须由所有者提供明确端口，注销操作也有归属。扩展端口必须有实际调用者和失败语义，不能以通用 Hook 绕过依赖规则。

- 组合根装配身份、授权、项目及业务服务；模块导入本身不启动网络、任务或连接。配置解析、初始化、开始接受请求和关闭资源有明确生命周期，初始化失败释放已取得的资源。
- 身份只提供可信账号状态；项目及资源所属模块提供真实归属事实；授权据此裁决。调用者提交的项目 ID、管理员标记或 capabilities 不作为可信事实。授权模块不直接查询其他模块的业务表，身份读取也不反调业务权限，避免相互依赖。
- 一个用例需要多模块原子变更时，由明确的应用协调服务通过各模块公开方法参加同一事务；事务句柄只提供机制，不能借此跨模块执行 SQL。所属模块依然负责数据不变量。
- 跨模块聚合读取使用公开查询能力；确有性能需要才建立带来源和版本的只读投影，明确更新、失效与重建方式。投影不成为第二个写入口，最终授权与关键执行条件仍查权威来源。
- 需要立即成功/失败结果的规则使用显式调用；仅结果通知等可以异步。必须可靠送达的事件与业务写入一起落盘，消费者按事件身份去重并有有界重试和可查失败记录；无需可靠性的局部刷新不引入持久消息设施。
- T3、资源协议、机柜及客户宿主分别在适配边界转换外部合同和错误。外部类型、SDK 对象与异常不穿透领域；依赖变化只影响适配层及相关合同测试，不迫使业务模块跟随内部实现。

## 账号、角色与资源授权

采用本地账号密码登录，持久化真实账号；新安装不预置 Demo 账号或通用默认密码。内部成员可以建项目并成为项目管理员；平台管理员创建账号，平台及项目管理员添加已有成员和分配项目角色。普通成员不得授予权限，外部账号不能自行创建项目。

角色、页面与成员配置统一遵循已确认的[项目权限设计](project-workbench-design.md#项目权限设计)，本规范不重复角色矩阵。采用固定角色、模块查看与业务操作、项目及环境范围；不建设逐 MCP、数据库、工具、文件、仓库分支、服务或部署目标的成员授权表。服务端仍解析每个对象的真实归属并校验操作，不把“不单独授权”理解为“不检查对象”。

项目级动作使用项目角色；环境级动作使用该项目环境唯一生效角色。成员显式获得可用环境，默认沿用项目角色，也可为该环境指定普通环境角色；显式值替代默认值，不与更宽项目角色或其他环境角色合并。平台及项目管理员保留既定管理范围，普通环境角色不能授予项目管理权。项目管理员管理其项目，普通成员不自动获得新增环境。全局机柜仅内部成员可操作，重置配置仅平台管理员维护。

问答使用权与会话环境范围同时满足时，可调用该环境内全部已启用的只读 MCP；连接读取范围由有项目管理权的管理员在环境中统一配置，不增加独立查询授权。环境 MCP 只能在环境配置维护。部署查看与操作由环境角色区分，服务和位置继承环境范围；共享节点的全局撤销及存储管理仍按全局管理能力判断。角色权限粗细不改变只读能力、数据归属、私有会话和设备所有权边界。

助手仅提供预设。服务端根据成员的“允许调整问答配置”能力校验最终参数：受限成员符合已分配预设，有调整权者符合当前允许范围。后续执行使用校验后的实际配置，不重新读取默认值覆盖合法调整；所用环境从会话绑定解析，不由模型调用自行改写。凭证受控使用随合法业务操作，不给普通用户新增取密权限。

每次操作检查账号有效、功能启用、动作授权、真实资源范围与业务状态。动作和范围必须在同一生效角色授权内匹配，禁止将测试发布权与生产查看权拼接成生产发布权。内部/外部资料、环境以及私有/共享分别判断；共享会话仍受资料和环境权限约束。

稳定动作标识例如 project.members.manage、workspace.read、workspace.external.publish、skill.assign、deployment.execute、deployment.rollback、credential.use、credential.manage。动作目录作为服务端与客户端的共同合同；客户端使用服务端 capabilities 展示入口，服务端对实际请求重新裁决。

文件、附件、报告、下载、日志、搜索、工具调用和后台任务使用同一授权机制。身份从可信会话或持久任务解析，不信任请求参数自报身份。凭证使用与管理分开，只向获授权的服务端操作解析凭证，不向界面、普通 API 或日志返回已有明文。

每个可调用业务能力在同源动作合同中声明动作、允许角色模板、所需范围及额外限制；公开业务入口到动作的映射必须可核对，不能漏掉下载、搜索和后台入口。动作标识用于执行和审计，不要求每个标识暴露独立授权开关。批量操作逐个验证真实资源，不能只校验第一个对象。接口只接受明确的可写字段，客户端不能通过附带所有者、角色或归属字段越过专用管理流程。

提交、任务领取和外部动作前重查当前授权；撤权后禁止新执行，失效相关能力缓存及订阅。已发出的外部操作跟踪真实回执，必要恢复使用可审计系统身份且限定原任务目标，不能凭超时认定停止或安全重试。默认不增加组织审批流。

用户提供的助手按[统一助手目标](project-workbench-design.md#统一助手与用户提供的运行来源)接入。来源共享记录归运行来源模块，项目助手分配归助手模块，权限模块结合真实调用者裁决；不能将调用者替换为设备提供者。客户端模型与思考强度来自绑定运行器的能力目录，执行前复核；共享撤回、能力失效和执行隔离都必须落在真实接口，未完成时不开放跨用户执行。设备管理与扩大本机权限仅由提供者操作，管理员没有代替提供者共享或取密的能力。

## 合同、数据与任务

- 公开输入同时具有运行时校验和同源 TypeScript 类型；统一稳定错误码、请求关联标识和模块资源标识。跨模块传引用与 DTO，不传可修改的内部存储对象。
- SQLite 使用模块自有关系表、外键、唯一约束和索引；启用可靠事务与数据库版本管理，不以单个 JSON 字段保存整份应用状态。网络请求、构建与大文件处理不放入数据库事务。
- 同一业务操作只保留一个应用服务入口，网页、工具和后台流程调用相同业务规则。模块内业务写入与必要审计、待发送事件原子保存；跨 T3 与业务存储的交互依靠持久收据、幂等及状态核对，不假设跨库原子提交。
- 耗时操作返回任务收据。幂等标识同时绑定操作、操作者、业务范围和参数；重复请求返回原结果，相同标识不同参数返回冲突。幂等记录不替代当前授权校验。
- 任务固定源码、资料和配置版本，保存校验值及凭证版本引用；页面切换、配置变更不能暗中替换输入。凭证撤销仍阻止新的凭证使用。
- 各业务模块拥有自己的任务状态机；T3 拥有聊天轮次和队列。统一视图可以展示标准摘要，不能覆盖原生状态或重新实现执行器。
- 任务区分排队、执行、取消请求、确认结束及结果待核查，名称可沿用所属模块或 T3 原生状态。取消请求不等于已停止，超时不等于外部动作失败；重启后核对持久收据和外部事实，不能把执行中状态直接改为成功或重新投递。失败后的恢复也是需要跟踪结果的业务动作。
- 网络结果未知时保持待核查状态，使用持久命令身份核对；不自动重发输入、不伪造完成或停止。已完成、失败、恢复结果与当前运行状态分别表达。
- 日常资料与固定输入版本分开。运行任务和保留部署版本保护依赖；允许删除的历史来源删除后显示已删除，不改用最新版本替代。私有成果只有显式保存后才进入相应项目范围。
- 源码包属于部署交付物，独立选择并固定各仓库 Git 提交，保留构建上下文、构建配置及校验清单；不默认收录上传的产品、运维资料。服务与部署位置分开，发布和恢复规则复用已验证能力，不能因替换页面遗漏阶段、日志、快照和历史。

## T3、客户宿主及扩展接入

业务层只维护 T3 的业务范围和授权绑定。首次输入被持久接受后固定项目、环境、内部/外部范围、助手及执行目标；每轮自动捕获当前资料输入，下一新轮重新获取最新内容。原命令重试、排队、恢复及子任务继续使用同一持久输入，不因资料更新漂移；接受结果未知时冻结绑定并核对原生收据。不得另建聊天事件、队列、恢复或技能输入流程。

会话可见范围是独立的会话属性，具有当前项目问答权限的会话创建者（无需参数调整权）在开始对话后仍可随时切换“仅自己／项目共享”。只修改当前阅读范围并同步原生子任务，不能借此改变执行参数、提交收据或历史输入；其他成员不能修改可见范围；已保存的平台会话也无需参数调整权。电脑所有者主动将自己的本机会话设为项目共享时，授权符合项目及环境范围的成员沿该会话原电脑、目录和能力继续操作，无需重复分配助手；不授予另建自用会话或改投其他电脑的权限。提供者不是会话创建者的来源仍执行原提供者共享与分配校验。改回私有后拒绝其他成员的新操作及未开始的排队执行，已执行副作用不回滚；已开始轮次保留原结果并由所有者控制。每条消息和排队请求记录真实调用者，不能冒充电脑所有者。服务端重查所有者与项目权限，以原值防止并发覆盖；列表、附件、搜索、后续实时结果及工具访问使用当前可见范围。显式保存到项目的成果保留其独立生命周期，不随会话转私有撤回。

平台问答仅获授权读取外部资源及生成报告；用户具有发布权限也不自动赋予模型部署工具。客户本机按设备所有者、登记目录和本机权限执行，平台只读边界不扩散到本机，本机权限也不能扩大平台权限。客户事件可靠确认、去重和执行状态使用共享协议机制。

技能发现、输入标签、预览和实际读取使用同一授权的不可变快照；平台与本机技能来源分离，停用或撤回后拒绝新调用。未具备脚本或依赖执行条件的技能只能保存预览，不能分配调用。

MCP 和插件接入须声明作用范围、启用条件、动作权限、配置合同、工具能力及健康状态。优先复用成熟实现，通过受控入口适配；预置只读工具须有真实只读权限和限定动作。停用后拒绝新调用，历史结果继续按当前阅读权限提供；不能靠插件页面隐藏实现停用。

## 故障隔离与资源预算

模块化单体共用进程与数据库，划分目录不能保证所有故障互不影响。必须限制业务异常和外部依赖的影响；公共数据库不可用、进程崩溃等共享故障如实报告，依靠恢复流程处理，不宣称完全隔离。

| 故障或边界 | 必须采取的行为 | 第二步的验证例子 |
| --- | --- | --- |
| 单个外部资源离线或慢响应 | 连接、调用、输出有预算；失败归属资源/任务；同资源重试有上限，不阻塞全局请求 | 让一台目标超时，其他项目查询、导航与无依赖任务仍可用 |
| 模块页面或请求异常 | 返回稳定错误，模块区域显示失败；不使公共壳卸载，不把错误显示成空数据 | 注入工作区接口失败，仍能进入并使用不依赖它的部署查询 |
| 构建、归档、Git 等长任务 | 使用受控进程/既有执行器，有按目标及任务类别的并发和排队上限，限制输出/磁盘占用 | 耗尽某类任务容量时拒绝或有界排队，登录及状态查询仍响应 |
| 非必要通知或汇总失败 | 保留权威业务结果，记录失败并允许重建或重试；不撤销已成功发布 | 通知发送失败后发布状态保持真实，通知失败可定位 |
| 必要审计持久化失败 | 本地事务内的业务变更回滚并明确失败；不能以丢失审计换取成功 | 本地事务写入未生效，已有数据的获授权读取不被人为关闭；已发出的外部动作另按收据核查 |
| 身份、授权或核心存储不可用 | 拒绝依赖它的操作，不使用过期授权兜底；公共壳显示实际不可用范围 | 不能因授权服务异常放行或靠切模块绕过拒绝 |
| 共享进程发生不可恢复异常 | 记录最少诊断信息，停止接受新操作并按宿主机制退出/恢复；不捕获后假装健康 | 恢复后核对任务收据，避免重复外部副作用 |

外部动作已经发出后，保存回执或审计失败不代表动作未发生，不能声称外部效果已被本地事务回滚。保留既有持久命令身份，阻止盲目重发，恢复后核对外部结果并补记必要事实。

每类外部操作在所属适配器声明超时、取消、重试条件与次数、并发、排队、输入/输出大小限制，并使用统一配置边界校验；具体值在第二步结合现有机制与目标容量确定并测试，不另造调度框架。重试须考虑幂等性和当前授权，避免层层重试造成成倍执行。

页面退出只取消所属页面的临时读取并释放界面订阅、计时器等资源；已提交的业务任务，包括排队中的任务，继续遵循服务端或 T3 的任务生命周期。只有显式取消、撤权、模块停用等规定事件才拒绝或取消尚未执行的动作；服务正常关闭时停止领取新任务，持久队列在恢复后重新核对权限和输入。已开始的外部动作按真实回执跟踪，不因页面关闭销毁状态。模块负责释放自有连接、监听和临时文件；共享文件按所属模块的引用规则清理，不用全局清理器绕过业务保留条件。

## 运行生命周期

- 运行宿主拥有初始化与释放顺序，业务模块只释放自己创建的资源；共享连接由其所有者在使用者完成后关闭。复用宿主已有作用域和释放机制，不增加全局退出管理框架。
- 初始化中途失败也必须释放已取得的连接、监听和子进程。重复关闭返回同一关闭结果或安全完成；进入关闭后不允许通过惰性访问重新创建已关闭实例。
- 正常关闭先停止接受新的业务操作与领取任务，再等待已接受操作及必要结果落盘，最后释放依赖。每类后台任务明确排空、可恢复保留或协作取消策略；远端动作不能因本进程退出被伪造为取消或成功。
- 排空预算和监督器的最终退出上限必须由运行环境控制；模块的协作取消预算不能冒充整个进程的硬退出上限。超出预算如实报告未完成，保留持久身份供重启核对；不得先关数据库再让未完成任务继续写入。异常强制退出与正常排空分别验收。
- 验证真实宿主的释放路径，以及关闭期间的新请求、正在执行的任务、重复关闭、部分初始化失败和重新启动；仅有未被调用的 close 方法不算接入完成。初始化、迁移或维护逻辑改变时，用代表性测试数据验证连续启动和重复执行，核对本用例标识、首次处理事实及显式空值语义；不要求复用历史实例身份，只重开数据库不能替代服务初始化。

## 数据升级、配置与可运维性

- 升级文件按模块拥有表结构、按全局有序版本执行，已应用版本及校验值持久保存；修改已经应用的升级或遇到未知数据库版本必须停止启动。升级在事务内完成并验证外键，不在失败后继续服务半升级数据库。
- SQL 参数化，关系用外键/唯一约束表达；成员、授权、配置版本和任务身份不能只依赖前端判重。事务协调器只负责提交/回滚，模块通过公开接口写自己的表；不要把业务表查询搬进公共数据库工具。
- SQLite 外键、忙等待、持久化策略明确配置；同步事务中不得 await 网络、密码计算或大文件处理。持久化冲突有稳定错误语义，配置写入采用版本条件，避免多人操作静默覆盖。
- 正式启用后的升级先备份再执行，SQLite 使用一致性备份方式，不能只复制活动中的主文件而忽略 WAL；恢复需要实际演练并核对数据与文件版本。失败回退说明数据库兼容范围，不假设换旧二进制即可恢复。
- 当前开发测试发行不以历史账号、会话、全表全文件、原 CLI 身份与账本或认证窗口的全量保留作为硬门禁，已有保留审计仅作历史证据。本次功能用例涉及的收据、源码包、附件及固定输入仍按所属模块合同核对真实生命周期；重建测试数据后以新夹具继续验证权限、幂等和恢复，不把删除未知结果或重置基线当作业务恢复通过。正式启用或生产环境的数据保留另按不可变事实与合法生命周期变化逐项核对。
- 维护窗口前按实际执行身份核对运行时、路径、网络、资源及恢复条件，复用现有发布工具，明确排空、切换、健康及失败恢复的有界预算。当前开发测试可按上述策略重建实例；正式启用或生产环境须可靠保存基线与恢复依据并保全新增数据。无法继续时恢复服务或按适用策略重建，不在停服后无限调试辅助工具。具体命令和预算由当前发行运行说明维护，规范不替代现场授权或扩大到外部服务的清理范围。
- 运行配置在启动边界解码：核心配置缺失/无效阻止启动；未启用模块不要求其连接配置；已启用模块配置无效则明确标记该模块不可用并拒绝相关操作，不静默忽略。若该模块是某功能的必需依赖，只限制该功能链；核心必需依赖失败才影响全局就绪。生产秘密由运行环境提供。新安装管理员通过明确的一次性初始化流程创建，无固定通用密码；密码使用成熟派生算法，会话只保存令牌摘要、有到期/注销/停用语义。
- Cookie 登录采用 HttpOnly、适当 SameSite 和按部署环境启用 Secure；状态修改请求校验来源及 CSRF，登录有有界限流。API 不接受请求自报用户；无权限、账号停用和资源不属于当前项目均由服务端拒绝。
- 外部连接设超时、取消和有界重试；只重试可安全重复或有持久幂等身份的动作。文件/归档读取校验真实路径、链接和解压边界，上传、解析及搜索有大小与资源预算。复用现有成熟实现，不新增无限队列或任意命令执行入口。
- 健康检查区分进程存活、核心就绪与模块/外部连接健康；可选外部资源暂时离线不使无关功能或全局就绪失败。检查有界且不产生业务副作用，公开返回最少信息；内部异常用请求标识定位，响应不返回堆栈、SQL、路径或秘密。关闭时停止领取新任务并正确关闭连接；已经发出的外部动作保持真实待核查状态。
- 日志用于诊断，审计用于追溯操作，任务记录用于业务执行，三者不可互相替代。审计与对应业务变更同事务保存，内容只含允许字段；失败写入不能留下业务成功而必要审计丢失的状态。

## 验收与维护

模块边界和非法依赖由自动化检查约束；合同测试与真实授权测试覆盖 HTTP/RPC/MCP、文件下载及后台执行。验证跨项目、跨环境、外部范围、私有数据、角色组合、撤权、幂等、配置冲突、故障恢复及真实外部接入。

按受影响范围运行检查，交付版本回归核心业务链；模拟数据只能证明模拟场景，不能作为真实连接、部署或模型调用的验收证据。实现检查时不得只匹配源码字符串或复制实现断言。

当前开发的 D6 保留期清理可使用可控时钟或隔离测试 TTL，实际运行所属模块的清理流程并核对到期删除、未到期及活动引用保护；不必自然等待 7 天。记录所用测试条件，不修改生产默认 7 天，也不以只计算到期时间或手工删除文件代替清理验收。
