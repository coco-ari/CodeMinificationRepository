## 本轮发现及处理

1. B 的 Docker 镜像代理返回 HTML，默认 Agent 构建失败。通过官方 ECR Public 源预拉取 `node:24-alpine` 和 `docker:29-cli` 后，原安装脚本及标准中心 Dockerfile 构建成功；没有修改全局 Docker 代理设置。全新服务器仍须先满足镜像和包源可达条件。
2. macOS 的打包命令附带扩展属性，Linux 解包出现警告。打包脚本已排除 xattr/AppleDouble；macOS 和 Linux 构建的安装包均检查为 16 个程序文件且无此元数据。
3. Alpine 全量测试初次缺少夹具所需的 `git http-backend`，导致一项 HTTP Git 测试失败。补齐测试容器的 `git-daemon` 后重新验证；没有扩大生产镜像依赖，也没有跳过失败项。
4. 原 A 的部分服务间调用指向容器自身的 localhost，Agent 验证环境已使用 Docker DNS 覆盖；原 Jenkins 参数保持不变。A 实际为宿主机 Nginx，前端 Docker Nginx 场景在独立环境验证，没有改造 A 的 Nginx。
