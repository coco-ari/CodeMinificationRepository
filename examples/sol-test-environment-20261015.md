# 越南 SOL 单一测试环境整理（2026-10-15）

越南 SOL 标准版现在只保留一个 **测试环境**，四个 Java 服务均使用原 Agent 验证的可发布配置。环境名称不决定部署能力；目标的 `managed` 模式以及服务器的管理能力决定能否发布。

## 最终结构

- 项目：`bf24f60e-f0ad-4f15-8520-b93d112f65b0`。
- 保留环境：`2fb57ec7-e8d0-4fa1-b919-48b210bbd0e6`，由“Agent 验证”改名为“测试环境”。已有任务和配置链接继续有效。
- 保留服务：`brezze-api`、`brezze-communication`、`brezze-manage`、`brezze-reward`，共四个平台管理目标。
- 完整保留四个目标的 ID、容器名称、源码关联、端口、运行配置、9 条任务记录和 5 个版本记录。
- 原环境 `5294b127-a32e-4b7c-adc9-318609fc7934` 及其四条 Jenkins 只读观察记录、四条重复源码关联，经备份后从中心移除。这些观察目标没有发布任务或版本记录。

该操作没有执行发布、启动或停止 A 上的容器，也没有修改 Jenkins、Nginx、数据库、下载密码或 Agent 身份。原业务域名仍指向 Jenkins；平台测试服务继续使用 localhost 的 20110、20111、20112、20115 端口，操作方式见 [Java 服务部署手册](java-operator-manual.md)。

## 执行与验证

1. 检查两个环境的服务、服务器及仓库分支对应一致，确认没有进行中的发布或源码同步。
2. 短暂停止 B 中心，完整备份数据卷，在 SQLite 事务中整理上述记录，再启动同一中心镜像。
3. 对比受保护数据摘要，确认仓库、凭证、管理员、Agent 身份、四个平台目标配置和全部发布历史未变。
4. 公网桌面和手机验证：项目只显示一个测试环境，四个目标均为平台管理，API 的确认发布按钮可用，两个 API 历史版本可读；未提交发布任务。
5. 验证旧测试环境 URL 自动回到现有测试环境、Agent 心跳恢复且上报四个目标。B 其他 15 个容器的 ID、启动时间和重启次数均未改变。

## 维护记录与恢复

B 上的 `/opt/cmr-upgrades/20261015-sol-test-environment/` 保存整理脚本、前置检查、变更结果和后置检查；`backup/` 保存完整数据卷及 SQLite 副本，仅 root 可读。运行镜像仍为 `code-minification-repository:d472ffc`，本次不涉及程序升级。

如必须恢复整理前结构，应先停止中心并备份最新数据，再评估整理后是否已有新的发布记录。只有确认不会覆盖新记录时，才能恢复本次备份；若已有新记录，应根据备份恢复旧观察环境的配置，而非覆盖整个数据库。恢复中心配置不会自动操作 A 的容器。
