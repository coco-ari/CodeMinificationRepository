# 源码快照与 AI 运维接入方案

## 目标

保留现有自动化部署的完整 ZIP 接口，增加独立的 `cmr-source/1` 快照协议。云端管理员配置 Git 来源及定时同步；普通客户端只能读取固定快照，首次完整下载、后续按文件 SHA-256 增量同步。Git 仅在服务端运行。

## 兼容性

- `/api/projects/:id/source/latest` 继续按请求检查上游、返回 ZIP 和原响应头，失败不返回旧包。
- 复用项目下载密码、停用/换密码立即失效、指定 Gitee 分支、凭据加密及全局同步队列。
- 后台新增快照开关及同步间隔，旧项目默认关闭，新数据字段缺失有兼容默认值。
- 新快照失败单独记录，不阻止已经成功生成的部署 ZIP 交付。
- 现有导出排除、LFS/子模块限制保持；不自动扩展 Git 来源范围。

## 协议

全部路由位于 `/api/v1/projects/:id/source`，要求项目 Bearer 密码；不接受 Git URL、任意 Git 提交、任意服务器路径。

| 路由 | 说明 |
| --- | --- |
| `GET /head` | 查询发布指针与同步状态，不执行 Git |
| `GET /snapshots/:snapshotId/manifest` | 不可变文件清单：版本、提交、创建时间、导出策略版本、文件路径/类型/权限/大小/SHA-256、总大小 |
| `GET /snapshots/:snapshotId/archive` | 固定版本 ZIP，首次下载使用 |
| `POST /snapshots/:snapshotId/files` | 有界文件哈希列表，仅返回此项目此快照引用的内容，批量传输 |
| `GET /events` | 鉴权 SSE 版本信号；断线客户端重新读取 head |

客户端比较目标清单与已验证本地文件，发送缺少对象。删除由新清单表达，换名可以复用相同内容；跳过多个版本也不需要中间补丁。批量响应、总导出大小、单文件大小、文件数都有上限。共享对象仍按项目及快照授权，知道哈希不能跨项目下载。

## 存储与发布

复用 ArchiveBuilder 固定的提交与 Git 导出结果。哈希基于实际交付文件，不能绕过 `export-ignore`。首先完成文件对象，再写完整清单和 ZIP，最后原子切换发布指针。大清单与正文存在独立目录，不放进频繁整体重写的 state.json。

快照 ID 是不透明的不可变身份，不允许客户端选择未发布 Git 历史。清理保留当前和宽限期内版本，保护活跃下载。新构建临时目录失败清理；重启后发布指针必须可验证。安全路径校验覆盖父目录穿越、绝对路径、反斜线、控制字符、保留目录、大小写冲突和链接；不执行源码或构建脚本。

## 定时与通知

每项目管理员设置间隔，0 表示关闭；无历史配置默认关闭。调度任务错峰，同项目合并，复用全局队列，不可重入。上游失败记录状态并重试，保留已发布快照但明确其时间；旧 latest 接口仍保持失败即错误。SSE 只发送项目版本信号，不能携带令牌或私有服务器路径；换密码/停用后关闭已有订阅。

## 管理端

项目表单新增“启用源码快照”和“自动同步间隔”；卡片区分 Git 同步、ZIP 与快照状态，展示提交、文件数、内容大小、上次成功及失败提示；提供只读接入地址。原下载页面和 Jenkins 示例保留。

## 验证与交付

现有 11 项回归全部保留；新增真实 Git/HTTP 测试覆盖清单内容、首次全量、增删改、无变化、跨版本、导出排除、失败发布、授权和凭据轮换、损坏对象、限额与清理、重启、调度与 SSE。浏览器 smoke 验证新设置与旧管理流程。AI 运维仓库使用同一协议完成真实临时服务集成测试。

本次只提交和推送代码；部署需独立核对运行版本和数据备份，不执行清空数据卷等破坏操作。
