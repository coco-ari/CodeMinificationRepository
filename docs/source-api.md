# AI 运维源码快照接口（cmr-source/1）

这是原 Jenkins / ZIP 服务之外的只读快照接口。项目默认关闭此能力；管理员在项目表单开启后，通过「立即同步」或自动同步生成快照。客户端只能读取已发布版本，不能指定 Git 地址、分支、提交或修改云端代码。

管理端提供三项配置给源码插件：服务根地址、项目 ID、项目下载密码。不要把原 `/source/latest` URL 填作服务根地址。源码密码与旧下载密码相同；所有以下接口都要求 `Authorization: Bearer <项目下载密码>`，不接受 URL 密码。

基础路径：`/api/v1/projects/{projectId}/source`。

| 方法与路径 | 结果 |
| --- | --- |
| `GET /head` | 协议、项目、已发布 snapshot、同步状态及限制；不触发 Git |
| `GET /snapshots/{snapshotId}/manifest` | 固定版本清单，文件路径、权限、大小、SHA-256 与归档摘要 |
| `GET /snapshots/{snapshotId}/archive` | 固定版本完整 ZIP，用于首次同步 |
| `POST /snapshots/{snapshotId}/files` | JSON 请求 `{ "hashes": ["文件SHA256"] }`，有界返回清单内的文件对象 |
| `GET /events` | SSE 变化信号；客户端收到信号后重新鉴权查询 head |

客户端比较完整目标清单和本地对象库，可以直接跨多个版本更新；不依赖中间差异包。`files` 响应包含 `files: [{sha256, data}]`，data 为 Base64；接受 gzip 的客户端会收到压缩 JSON。单批最多 128 个哈希、原始内容合计 16 MiB。重复内容按哈希复用，删除和重命名由目标清单确定。

快照 ID 是规范 JSON 的 SHA-256，字段顺序为 `projectId`、`revision`、`exportVersion`、`sourceIdentity`、`files`；文件按路径排序，每项字段依次为 `path`、`type`、`mode`、`size`、`sha256`。具体字节约定与路径校验以 `src/source-snapshots.mjs` 和客户端协议测试为准。

源码来自实际 `git archive` 输出，因此遵守 `.gitattributes export-ignore`。不包含 `.git` 历史。每快照最多 20,000 文件、256 MiB 原始内容，单文件 16 MiB；只接受普通文件。绝对路径、上跳路径、符号链接、特殊文件、大小写冲突和 Windows 保留名称等不可安全同步内容会被拒绝；不会擅自改变原 ZIP 接口的导出行为。

先写对象和清单，再原子发布 head。快照生成失败时保留上次发布版本并在 head 中报告失败，客户端能明确识别旧版本；原 `GET /api/projects/{id}/source/latest` 仍要求本次 Git 同步成功，失败不会返回旧包。

## 自动同步与通知

自动同步仅作用于启用项目、启用源码能力且设置了非零间隔的项目。支持 1/5/15/30/60 分钟，启动时错峰；共用原有 Git 队列、并发合并和超时。连续失败按间隔的两倍逐次退避，最长一小时，成功后恢复正常间隔；管理员仍可手动触发。

SSE 不传文件、密码或 Git 凭据。重置密码、停用项目或修改来源会关闭旧订阅；后续请求重新鉴权。SSE 每 15 秒保活，每项目最多 32 连接、总计 256；源码请求每项目每分钟最多 180 次，失败鉴权另限流。断线可用一分钟轮询兜底，客户端更新仍由用户决定。

同步不会推送替换本地文件。已下载内容无法远程收回。

## 缓存与错误

`sources/` 保存项目隔离的对象库、不可变 manifest/ZIP 与 head。保留当前快照、至少一小时内的快照和持有下载租约的快照；后续同步会清理无引用对象。客户端应先固定 snapshotId，再获取清单/内容；过期返回 `410`，重新查询 head 后由用户选择新的目标版本。

主要状态：`401` 无效密码或项目停用；`409` 源码能力未启用、未发布或来源尚未就绪；`410` 版本不存在/过期/不属于当前来源；`413` 请求过大；`422` 导出内容不受支持；`429` 频率或订阅数量超限。错误正文不包含 Git 凭据。

来源地址或分支变化会清除发布关联，禁止通过新来源的接口下载旧来源快照。下载密码重置后，尚未发出的异步响应会再次检查鉴权；已发送的数据无法收回。
