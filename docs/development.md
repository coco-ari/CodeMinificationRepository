先读 [AGENTS.md](../AGENTS.md)，再按 [规范索引](README.md)选择任务相关专项。重建顺序见 [分波计划](../examples/autoops-rebuild-plan.md)。

## 当前状态

规范已整理，第一波工程基座与项目/环境/权限切片正在实现；可执行的新入口和验证结果将在本波完成时更新。本段是实现状态，不能用目标规范代替已完成的业务。

现有工作台仍由 `agent-demo` 宿主、`vendor/t3code` 及业务适配器组成；旧部署中心在 `src`，旧控制台和原型在 `web`。这些入口用于既有验证和业务参考，不是新模块的默认依赖。现有启动、真实环境操作与历史验证见对应目录和 [历史平台说明](history/legacy-platform-readme.md)。

## 开发约定

- 使用根 `package.json` 固定的 pnpm，依赖安装用 `pnpm install --frozen-lockfile`。新模块的 Node 版本与 TypeScript 选项随实现显式记录；T3 自己的锁定运行条件仍按 vendor 清单核对。
- 测试只使用临时数据库、临时目录和受控连接；不得把新服务指向已部署环境数据或从旧 Demo 自动导入。
- 检查命令区分新产品与历史代码。旧 `pnpm check` 主要检查旧部署脚本与 `web`，不能作为新后端或 T3 全部代码通过的证据。
- 改动 T3 原生交互时运行相关类型、构建及定向测试；改动公共执行模块同时验平台和客户宿主；改动视觉时按 UI 规范做真实页面检查。
- 报告具体命令、结果与未测边界；普通开发不触发真实模型、发布或设备操作。需要真实环境验证时使用任务已授权的目标和范围。
