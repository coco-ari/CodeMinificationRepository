# AutoOps 规范索引

维护规则的目的，是让开发者和 AI 能快速找到权威约束，并用代码检查兑现。不要把同一规则复制到多个文件，也不要把所有规范一次塞入每个任务的上下文。

## 当前定稿状态

开发规范基线 v1 已整理完成。执行顺序为先定规范、再优化全部现有模块、最后新增功能；当前分支是唯一功能基线。当前步骤、定稿依据与代码的实际符合性统一在[开发与验证](development.md#当前状态)记录；本次文档完善不代表模块优化已经完成。

## 维护方法

- 业务规则变化：更新业务需求及相应专项规范，合同和测试同步修改；不在根入口追加长篇实现记录。
- 影响多个模块的决定：在相关规范写明背景、选择、替代方案不适用的原因及边界。局部代码技巧写在必要的中文注释里。
- API 字段、表结构和命令参数以代码合同、升级文件与可执行帮助为准，不手写第二套字段大全。
- 完整计划保留业务目标与流程，执行顺序服从用户最新的三步安排；早期阶段号只用于追溯，不能重新要求对照 main 或提前新增功能。实施状态只维护在开发文档，批次摘要不能取代业务要求。已完成的实施细节留在提交和测试中。临时日志、截图、调研下载保存在忽略目录或仓库外。
