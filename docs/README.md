# AutoOps 规范索引

维护规则的目的，是让开发者和 AI 能快速找到权威约束，并用代码检查兑现。不要把同一规则复制到多个文件，也不要把所有规范一次塞入每个任务的上下文。

规则与实现现状分开：专项规范是目标；开发文档及测试记录是当前证据。旧 Demo、旧部署平台、旧原型与历史评估只用于提取可复用的业务能力，不能成为兼容要求。[历史平台说明](history/legacy-platform-readme.md)不指导新产品的 UI、权限、数据或接口设计。

## 维护方法

- 业务规则变化：更新业务需求及相应专项规范，合同和测试同步修改；不在根入口追加长篇实现记录。
- 影响多个模块的决定：在相关规范写明背景、选择、替代方案不适用的原因及边界。局部代码技巧写在必要的中文注释里。
- API 字段、表结构和命令参数以代码合同、升级文件与可执行帮助为准，不手写第二套字段大全。
- 完整计划保留已确认的目标、流程和验收条件；实施状态只维护在开发文档，并按原阶段映射。批次摘要不能取代原计划。已完成的实施细节留在提交和测试中。临时日志、截图、调研下载保存在忽略目录或仓库外。
