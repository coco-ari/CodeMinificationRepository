# 当前运行模块与检查入口

这里记录当前分支的实现及调用边界，不替代[开发规范](README.md)。线上工作台仍由 `agent-demo` 网关、锁定 T3 和业务适配器组成；独立 `autoops/server` 的账号与项目后端另用 `verify:autoops` 验证，尚未替代线上身份或数据。历史目录中仍被调用的能力继续保留。

## 启动与装配

- `pnpm start:agent-demo` 启动[网关](../agent-demo/server.mjs)，T3 模式由 `AGENT_DEMO_ENGINE=t3` 选择；网关负责登录、同源 HTTP/WebSocket 代理与静态资源，不拥有 T3 轮次。
- `pnpm start:agent-demo:t3` 通过[启动器](../scripts/start-t3-worker.mjs)装配锁定 T3 worker，监听回环地址。`DATA_DIR`、`AUTOOPS_T3_BASE_DIR`、`AUTOOPS_T3_PORT` 及外置凭据沿当前部署配置提供；不得用测试默认值覆盖已有服务。
- T3 [HTTP 适配入口](../vendor/t3code/apps/server/src/autoops/http.ts)、[RPC 适配入口](../vendor/t3code/apps/server/src/autoops/rpc.ts)及客户接入入口，从认证请求取得身份后调用业务适配器。T3 原生会话、命令、事件及恢复仍由上游服务拥有。
- 前端由 [hostConfig](../vendor/t3code/apps/web/src/autoops/hostConfig.ts) 组合启动与公开出口；[hostSnapshot](../vendor/t3code/apps/web/src/autoops/hostSnapshot.ts) 只保存已认证宿主快照和用户存储视图，[threadScopes](../vendor/t3code/apps/web/src/autoops/threadScopes.ts) 通过统一客户端处理会话范围。页面继续使用当前 T3 路由与公共框架，组件不读取服务端表或凭证。
- 部署保留 [DeploymentService](../src/deployment.mjs) 与 [Agent](../agent/main.mjs) 的现有协议、构建及恢复；业务适配器只提供项目授权、独立 Git 源码包与公开 DTO。

## 统一助手管理与实际输入器（2026-10-26）

影响范围为助手唯一管理导航、原接入面板、纯助手合同及其 SQLite v2 升级、本人/项目目录、原生 HTTP 装配与实际 ChatComposer 选择和发送。继续复用 T3 ModuleWorkspace、SettingsSection/Row、Menu/Dialog、原电脑接入、模型选择器及原会话启动合同；不复制执行器，也不变更平台/用户运行位置。已有项目助手与角色/成员分配继续复用，旧 devices 路由重定向到助手的“我提供的”，保留显式项目范围。低权限仅显示获分配预设，项目管理者不能代提供者修改本人助手或共享授权。

本人来源来自登记目录及真实能力，不推测平台默认。提供者主动共享给明确项目，管理者随后分配；分配记录固定预设、共享修订与来源身份。提供者修改需要管理者重新确认，撤回拒绝新执行；原已接受配置沿原修订恢复。跨用户/跨项目执行仍明确拒绝：当前 transport、本机会话、目录、附件及技能尚缺完整的实际调用者隔离，不能删除硬拒绝就称为 C6 完成。旧接入/配对协议仍没有本批新预设的原请求收据，分别保留证据边界。

本批复现三类实际缺陷后修复：

- 模型目录移除当前模型后，原 Composer 从首项或平台默认补选。可能是后端目录错误：固定目录确认实际模型已移除，排除；模型解析器默认回退导致，新增最小失败回归证实。AutoOps 草稿固定原选择，无效模型/强度明确阻止发送，只有用户显式选择才能改变。原 T3 非 AutoOps 行为保持原合同。
- 项目管理并行读取同时返回 503 和 403，页面把首个 503 当总体失败、保留旧管理内容。可能为接口把撤权改写成网络错误，单接口 403 回归排除；聚合选择首个错误的失败用例支持根因。管理聚合现优先保留已知 401/403/404，撤权清除旧预设和表单，临时故障仍可重试。
- 提供者 HTTP 的有效 JSON 加超额空白仍返回 200，且正文等待、读取及写入后注销都能得到预设。可能为 Schema 未严格拒绝字段：同一合法参数的正常路径通过，多余字段已 400，不能解释正文和身份时序；Web Request 不执行 MaxBodySize、路由只核对初始登录为实际原因。`.deployment/provider-http-{body,revocation}-before.log` 保留 4 个失败；随后 `provider-http-project-revocation-before.log` 另复现项目管理权在返回前撤回仍返回来源，初始管理检查有效但返回前只刷新登录，现同时复核管理权。现从真实流限 64 KiB，异步后和返回前复查当前登录。写后撤权只返回 saved/available=false，客户端清敏感表单并保留明确恢复入口；重新授权后核对原收据，不自动创建新请求。

## 跨用户运行合同与真实 OS 验收（2026-10-26）
