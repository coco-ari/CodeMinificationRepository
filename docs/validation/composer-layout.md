# 问答输入区与可选助手预设

2026-10-31 按用户提供的截图和确认方案，整理原生问答输入区；权限、模型合同与直接配置规则继续见[直接配置验收](direct-question.md)。

## 实际变化

- 业务范围从外接叠层移入 `ChatComposer` 的原生工具栏，共用一个输入表面，不再叠加第二张配置卡片。
- 控件按环境、资料、助手预设、模型／思考强度、附件和发送排列。按输入区实际宽度布局，宽屏同行，窄屏范围一行、模型和操作一行。
- 默认入口为“助手预设”，菜单只列真实助手。平台预设可“取消使用预设”，电脑来源可“改用平台问答”；沿用原有范围保护和干净草稿流程，不引入新的执行模式。
- 范围控件使用共享控件的正常对比度，固定文字槽位、长值省略、完整说明和键盘访问保留。受限参数与已接受会话继续只读。
- 折叠、授权等待和窄屏下仍保留范围组件及其状态，避免重复读取已保存绑定；原生编辑、附件、停止、队列和菜单焦点流程继续使用。

## 验证

本地证据位于忽略目录 `.deployment/composer-layout/`。

- 五个直接相关文件 48 项通过，覆盖真实输入器的无助手发送合同、预设选择／取消、受限与电脑来源、菜单键盘、窄屏长名称和焦点。
- 新增的已有对话场景验证桌面与 390px 折叠／展开，范围始终存在、仅一次绑定读取、一个可见主操作；深色截图使用原生调色与浏览器主题同步接口生成。
- 几何检查确认范围位于同一输入表面内，没有外接配置条；宽屏同行，窄屏自然分行，页面无横向溢出。
- Web 类型、网页构建、ChatView 编译器 2 项以及 319 个运行模块边界检查通过。菜单用例保留禁用项拒绝与可用项实际选择断言，等待原生菜单取得初始焦点后再执行 End／Enter。

正式构建已通过 workbench 临时预览：1440×900 浅色、1440×600 深色与 390×600 深色三种窗口检查通过，业务范围均在输入表面内、没有外接叠层或页面横向溢出；实际助手菜单、空草稿预设往返、中文输入后 Esc 保留及输入焦点恢复通过，页面异常和会话绑定提交均为 0。截图与报告位于 `live-preview/`。

界面验收只登录、查看页面、操作未发送的本地草稿，不创建真实问答或执行工具；此前真实模型问答的授权待办不计为本次界面验收通过。workbench 正式发布结果在完成后补齐。
