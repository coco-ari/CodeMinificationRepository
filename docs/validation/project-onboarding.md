## 原因验证

- **候选原因一：新账号授权失效。** 核对账号创建、项目目录和助手合同：创建账号并不自动创建项目或分配助手，零项目是合法状态。不能由前端补发权限或生成虚构配置；排除为本次根因。
- **候选原因二：前端把合法空状态当错误，且缺少下一步。** 首页只有项目拒绝分支，项目目录渲染空分组，助手页要求选择不存在的项目。首页 2 个失败用例确认跳转缺失；目录创建、分配、助手往返用例确认入口缺失，随后实现修复。
- **本批实现审查补充：** 新增引导最初将显式空 `projectId` 误当首次使用、将默认助手离线误提示重新分配，均先取得失败用例再修复；显式无权项目仍拒绝访问。原基线助手页已经能够显示助手项的不可用原因，本批把该信息带到项目详情。
- **连续使用补充：** 已发出的旧刷新响应能覆盖新项目目录，失败用例出现“当前项目已不可访问”。取消旧请求后恢复通过；另一条撤权用例原基线已通过，不将它记为新增修复前失败。

测试初期存在夹具问题（公共框架触发未定义的运行器发现、文本匹配包含重试按钮）。已隔离不属于页面引导的连接并修正匹配目标；这些测试故障不计作产品缺陷。最终完整公共框架用例另行通过，未靠简化布局替代整页验证。

## 同条件操作对比

点击、填写、菜单展开、选择和确认分别计一次；以指定页面、相同账号权限和数据为起点，自动跳转不计用户操作。表中只比较本次改变的流程，未把已有助手编辑或发布过程算成本批实现。

| -------------------------------------------- | -------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| 零项目内部成员在 `/projects` 创建项目        | 顶栏创建 → 填名称 → 保存，3 次；正文空白，创建后没有当前用户问答准入入口。 | 正文创建 → 填名称 → 保存，3 次；自动进入项目详情，展示真实问答缺口。                              | 请求仍为一次创建写入；原对话框取消后焦点回到创建按钮，可按 Enter 重开。  |
