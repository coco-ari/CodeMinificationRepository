# 会话协作与输入区精简（2026-10-29）

## 范围与根因

已有输入区在锁定状态仍因菜单 footer 保留助手下拉及刷新；skill 同时存在底部下拉和行内命令；部分摘要使用不同宽度。共享电脑会话在旧准入中被强制私有，成员目录又仅按独立助手分配读取，因此单改菜单不能完成协作。

最小变更覆盖输入区控件、行内 skill 文案、会话可见性、原电脑运行目录/文件投影及调用者核验；复用 T3 `ComposerControl`、`ComposerContextLabel`、菜单与原运行队列。公开运行目录接口新增 `{threadId}` 读取已有会话，保留原 `{projectId, question}` 草稿接口。

## 行为与操作对照

| 同一目标 | 变更前 | 变更后 |
| --- | --- | --- |
| 已开始的会话更换助手 | 还能展开及刷新，含义与固定绑定矛盾 | 显示实际名称，只读，不可展开或刷新 |
| 添加 skill | 底部下拉、行内 `$`/`¥` 两套入口 | 只使用原行内入口；不清空预设配置 |
| 会话共享 | 电脑会话被拒绝，受限创建者菜单灰色 | 创建者打开侧栏菜单、展开可见范围、选项目共享，共三步；可随时改回 |
| 成员继续原电脑会话 | 需要另分配助手且私有约束仍拒绝 | 在已共享原会话内发送，沿原电脑、目录和能力执行 |
| 转回私有 | 历史限制不能完成往返 | 权限立即复核；未启动的成员轮次不重发，已开始工作照实记录 |

模型、思考参数和原生执行仍遵循对应合同。共享不授予更改他人可见性、创建其他电脑来源或绕过平台环境/资料权限。
