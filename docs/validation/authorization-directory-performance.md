# 授权目录性能审查（2026-10-28）

本批核对当前 `agent-demo → vendor/t3code → 业务适配器` 的授权目录、账号密码、凭证读取、流式脱敏和资料校验调用链。复用 b44b7bf8 已完成的同步授权读数边界；不关闭权限、缩短密码派生或缓存凭证明文。本次代码仅修改 `agent-demo/t3-adapters/project-directory/index.ts` 及对应测试，固定候选 `13d8ed34c1f103b30b462aa46c1651b0f383b4aa` 包含已协调的 d50cb4f0/fa4614c0 界面提交。

## 已复现的问题与修复

`catalog.projects → members → seed.users → accounts.users()` 对每个成员读取完整账号目录并作 Schema 投影；内置 a-project/a-report 又各调用一次 `catalog.projects`，仅为得到项目标识却重复构建全部成员及环境关系。b44b7bf8 复用外层目录读取，未消除目录内部的这层重复。此开销随项目、成员和账号数增长，并占用同步授权所在的事件循环。

修复后，单次项目目录投影只读取一次当前账号并以 Map 查找成员；内置助手直接读取有效项目标识，不重建成员。映射只在本次同步 getter 内存在，下次读取重新取当前账号、成员及有效项目；授权决定没有跨请求缓存，现有错误继续向调用方传播。

真实 SQLite 隔离样例通过 RuntimeAccounts 的公开账号创建接口建立 20 个账号、20 个项目、400 条成员关系，连续五次读取项目及两个内置助手。测量只覆盖目录投影，不包含密码创建及网络：

| 同一输入与输出 | 修复前 | 修复后 |
| --- | --- | --- |
| 每次账号目录读取 | 1200 次 | 1 次 |
| 五次耗时范围 | 72.38–82.13ms | 3.53–4.01ms |
| 中位数 | 74.29ms | 3.73ms |
| 项目 / 成员 / 助手项目数 | 20 / 400 / 各20 | 相同 |

原最小回归先失败：目录投影读取 2 次而非 1 次，内置助手读取 4 次而非 0 次。修复后验证目录内容相同、下一次改名立即可见、成员撤权立即拒绝；新增项目立即进入内置助手，指定项目助手范围不扩展。
