# skills 三级启用范围验证

日期：2026-10-29。设计入口：[项目工作台设计](../../examples/project-workbench-design.md#skills-启用范围)与 [T3 UI 规范](../../examples/t3-ui-standard.md#技能中央库适配)。

## 现象与原因

旧页面把业务身份 `a-project`／`a-report` 当作助手，跨项目始终显示“项目助手／报告助手”。旧解析只有项目和业务身份两级，项目关闭会阻断身份回退；对话还按预设 `skillIds` 再过滤，空清单导致项目启用也不能使用。

## 本批修改

- 模块名 `skills`，条目名 `skill`。范围为“所有项目”“当前项目”“指定助手”；前者优先于后者，上层启用后下层只显示继承，关闭上层按保留的下层配置生效。
- 指定助手使用当前项目真实、已启用的预设 ID；同一共享助手在不同项目的范围独立。切换项目只保留视图，不携带旧助手或未提交动作。
- 平台对话每轮和 `$`／`¥` 候选共用范围解析，不受旧预设空清单影响。已开始轮次的输入不改写；升级前快照不阻止旧会话继续。
- 包管理与“所有项目”由平台管理员操作；项目管理员可以管理本项目和本项目助手。范围不增加文件、环境、设备或工具权限。
- 索引升级为 v3，沿用现有包目录，保留包、主启停及项目范围；旧业务身份分配不自动转为全局或实际助手授权。工作区不再是额外的 skill 启用筛选层。
- 前端沿用 T3 卡片、Toggle、Popover、Select、Dialog，移除勾选装饰和跨项目目标堆叠；保留错误、等待、焦点、撤权清理和版本内容查看。

## 同条件交互差异

同一管理员、当前项目、一个已就绪未分配 skill：项目启用仍为卡片点击一次，但启用后整个项目对话都可用，无需再修改每个助手预设；所有项目启用增加一个明确开关。指定助手从直接显示所有旧身份改为菜单展开→选择当前项目真实助手，2步，换取正确归属与紧凑布局。上层启用后下层无需重复操作。固定版本仍显式调整，关闭范围不会悄悄升级版本。

## 待确认边界

用户要求“所有对话可用”，当前电脑助手只使用电脑本地 skill，平台与本机目录尚未互通。已询问是否也要向电脑运行器提供中央 skill。未收到答案前不把本机支持标为完成，也不部署一个表面显示继承、电脑实际无法加载的版本。若要求包含电脑助手，须继续实现对应运行器传递及真实执行验收；若仅平台，则需明确本机独立状态并相应过滤页面的中央范围配置。

实站浏览器还存在上一批记录的 `http://localhost:28887` 已保存拒绝设置；本批未尝试绕过。当前浏览器自动化仅运行独立组件测试页面。
