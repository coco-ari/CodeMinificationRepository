# 问答底栏与选择菜单精简（2026-10-28）

## 范围与原因

用户反馈底栏助手选择过宽、常驻无助手提示及刷新操作占据额外一行。沿锁定 T3 `fe27e8e3` 的 ComposerSurface、ComposerControl、Menu、Sidebar 会话操作菜单组合调整；不引入第二套组件，保留助手预设及执行范围锁定；按用户追加要求，将可见性从执行绑定锁定中分离。

- 底栏保留紧凑的助手、资料、环境和实际可用技能入口，助手名称预留宽度由 10rem 缩至 5rem。常驻“尚无助手”说明删除；没有可用助手时仍禁止发送，实际错误不伪装成成功。
- 刷新助手放入助手菜单，保留失败提示、重试及刷新期间防重复提交；已发送会话仍能刷新目录，但不能变更绑定。停用助手不进入候选；已启用但离线等不可用助手保留禁用原因。
- 会话可见范围移至侧栏会话的更多/右键菜单。草稿及已保存的会话均可调整；已发送或提交确认中不再锁定可见性。后端独立入口仅接受原可见性和目标值，校验所有者、配置权限并防止并发覆盖；同步子任务与助手配置镜像，记录同事务审计并触发列表刷新。执行来源、输入、收据不变，本机仅私有与成员权限仍保留。执行选择时再次读取账号和当前范围。
- 公共菜单单选、多选及模型、字体、代码语言等同类选择使用背景高亮与原 aria 语义，不再绘制选中勾；真实开关、表单复选框和成功状态图标保留。原菜单 `data-checked` 没有匹配 Radix 适配器实际属性，现改为 `aria-checked`，浏览器断言确认非透明选中背景。
- 字体菜单验证发现输入触发重复 open=true 时会清空搜索；仅首次打开清空，原键盘筛选用例恢复通过。

影响集中于 ThreadScopeControl/scopeSelection、共享 menu 与 contextMenuFallback、Sidebar/useThreadActionMenu 及其原有选择调用方。可见范围抽为同一适配入口，使用现有 scope 读取和草稿存储；已保存会话新增专用可见性写入口，沿原生列表快照通知更新，不建立另一套聊天状态。

13d8ed34 首轮实站确认主要改动生效，但发现新空草稿被 SidebarDraftBlock 的进入时冻结规则排除，输入后也需离开才出现；草稿尾部又只有丢弃按钮。为使移入列表的可见范围直接可达，本批补齐当前空草稿行（标题“新对话”，输入期间保持冻结）、紧凑草稿更多按钮和状态标签不拦截点击。丢弃仍在同一菜单。原两项菜单回归改为挂载真实 SidebarDraftBlock，不再用临时按钮代替入口；22 项输入器回归重新通过，类型通过。

## 同条件操作变化

以同一账号、同一未发送草稿为条件：刷新助手从常驻按钮 1 次点击改为展开助手菜单 + 刷新 2 次；调整可见范围从底栏展开 + 选择 2 次，改为会话更多/右键 + 可见范围子菜单 + 选择 3 次。低频操作增加一次菜单动作，换取常驻底栏去掉可见范围及整行提示/刷新；不宣称操作次数减少。原草稿、模型及助手选择保持。

窄屏实站另外复现子菜单被先裁剪到视口内、再判断是否向左展开，导致父子菜单重叠和点击立即关闭。改为按预期右侧位置先判断可用空间，初次及下一帧使用同一定位规则；390px 浏览器实际点击回归通过。
